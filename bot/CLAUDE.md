## Правила

- Ничего не деплоить и не трогать прод (Dockhost, боевую БД) без команды владельца; шаги выката — по одному, по команде.
- Расхождение с планом или требованиями — не решать самому: описать и остановиться.
- Секреты (`~/.config/autodc/*.secrets`, `.env`, вебхук Битрикса) — не выводить в чат, отчёты и репозиторий.
- **База бота на бою — `max_bot_db`** (контейнер `nocodb-postgres`). `$POSTGRES_DB` там = `root_db` (NocoDB) —
  для бота всегда `-d max_bot_db`.
- **NocoDB — бережное чтение:** одна инстанция для дева и боя (Dealers, каталоги, программы, ставки — общие),
  в одном контейнере с боевой базой бота. Читать точечно (`where`/`limit`, нужные таблицы), без массовых
  выгрузок и циклов по всем таблицам; запись — только по команде владельца.
  06.10 массовое чтение архива диалогов уронило контейнер nocodb по памяти (OOMKilled, лимит 1,5 ГБ) — общая NocoDB для боя: каталог лендингов и бот. Только нужные поля (`fields=…`), страницы ≤ 25 записей, пауза между страницами; массовые чтения архива и больших таблиц — только с разрешения владельца.
- Битрикс (портал b24-mxici0, общий для дева и боя): запись — только по команде; тестовые сделки удаляются
  по команде после холостого прохода (`scripts/bx_delete_test_deals.py`).
- Дев-стенд: Битрикс включать только по команде и после чек-листа E (план, «Остановка E»); стенд и туннель ngrok не выключать.
- Коммит — только при зелёном pytest (SQLite; перед релизом — и PostgreSQL `TEST_DATABASE_URL`), сборка кабинета —
  `npm run build:cabinet` / `npm run check:cabinet`.
