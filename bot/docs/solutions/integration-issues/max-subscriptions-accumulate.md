# Перед перерегистрацией MAX смотреть GET /subscriptions — POST копит, не заменяет

## Problem

MAX `POST /subscriptions` ДОБАВЛЯЕТ подписку, а не заменяет (в отличие от
TG setWebhook). У боевого MAX-бота при подготовке перерегистрации нашлась
вторая подписка на хост n8n (`…/max_webhook`) — мусор неизвестного
происхождения: по проверке n8n-агента такого вебхука нет ни в одном из 43
воркфлоу (POST отвечает 404 до вебхук-роутера), исполнений из неизвестного
источника нет. Пока подписка жива, MAX слал события и туда. Тот же механизм
даёт ДУБЛИ диалогов, если при переносе бота между стендами (дев→прод) не
снять старую подписку.

## Solution

`register_webhooks.py` работает по фактическому состоянию: `--check`
показывает ВСЕ подписки токена; `--apply` — POST нужной + DELETE всех
лишних (порядок POST→DELETE, чтобы не оставить бота без подписок);
`--deregister` снимает все подписки бота (для вывода из оборота/переноса).
Мусорная n8n-подписка удалена штатным `--apply`.

## Prevention

- Перед любой перерегистрацией/переносом MAX-бота — `GET /subscriptions`
  (или `--check`): подписки копятся годами и переживают смену стендов.
- Перенос бота дев→прод: сначала `--deregister` на деве, потом регистрация
  на проде — иначе дубли на два сервера.
- Сторож `check_max_subscriptions` (каждые 600 с) алертит о расхождении с
  подтверждённой регистрацией — дрейф виден без ручных проверок.
