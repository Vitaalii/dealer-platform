# После смены настройки ждать подхвата (перезагрузку реестра), потом проверять

## Problem

`--enforce` пишет флаг проверки секрета в снапшот БД, но работающее
приложение применяет его только при очередной перезагрузке реестра фоновым
воркером — интервал 600 с захардкожен (`bot_registry.registry_worker`).
Живое сообщение сразу после команды проходит по СТАРЫМ правилам: шаг
засчитывается ошибочно, а через ≤10 минут (после подхвата) бот может начать
молча дропать события уже на реальных клиентах — при несовпадении секрета.
Тот же паттерн у любых настроек, читаемых из кэша: реестр ботов (600 с),
справочник дилеров (600 с), сток (TTL 600 с), промпты (старт).

## Solution

В runbook: после КАЖДОЙ команды, меняющей поведение работающего сервера, —
дождаться маркера подхвата в логе (для реестра — свежая строка
`✅ [bot_registry] Loaded N bots…` со временем ПОЗЖЕ команды), и только потом
живая проверка. Откат (`--unenforce`) тоже действует после подхвата.

## Prevention

- У каждой команды из runbook явно указывать: когда изменение ДЕЙСТВУЕТ и по
  какому маркеру это видно.
- Проверка «сразу после команды» валидирует старое состояние — это ложный
  зелёный, худший вид ошибки выката.
