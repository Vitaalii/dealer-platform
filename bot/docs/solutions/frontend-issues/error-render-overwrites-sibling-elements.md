# Рендер области ошибки перезаписывал контейнер целиком

## Problem

Ручной тест дев-стенда: на экране ввода кода нет «Изменить номер» и таймера
повторной отправки. Оба элемента реализованы (U6), присутствуют в исходнике
и запинены grep-тестами — сюита зелёная, глазами элементов нет.

## Root cause

`renderSendFailureArea()` (состояния retry_free/delivery_failed/expired)
перезаписывала контейнер `#cab-auth-body` **целиком** через innerHTML и не
рендерила ссылку/таймер обратно. На дев-стенде без настроенного
SMS-провайдера эта ветка срабатывает **с первого же тика** поллинга
send-status — поэтому дефект выглядел как «элемента нет в вёрстке вообще»,
хотя корректный первичный рендер существовал и тут же затирался.

## Solution

Коммит `6b60cb8`: разметка и навешивание ссылки вынесены в общие хелперы
(`changePhoneLinkHtml()`/`wireChangePhoneLink()`), вызываются из обоих
рендеров области; добавлен grep-страж, что failure-рендер содержит ссылку.

## Prevention

- Диагностируя «элемента нет», различать **«не отрисовано»** и
  **«отрисовано и затёрто»**: если элемент есть в исходнике и в грепах —
  искать, кто перерисовывает его контейнер следом (innerHTML/outerHTML
  по родителю).
- Функция, перерисовывающая ОБЛАСТЬ, обязана владеть только своей областью
  либо восстанавливать всё содержимое контейнера — половинчатая перезапись
  создаёт состояние, невидимое для source-grep-тестов.
- Дев-окружение с отключённым провайдером — полезный усилитель таких
  дефектов: ветки ошибок срабатывают сразу и стабильно.
