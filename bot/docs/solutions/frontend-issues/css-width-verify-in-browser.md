# Ширина контейнера грепом по CSS не проверяется

## Problem

Итерация десктопной раскладки (коммит `6b60cb8`) была признана готовой по
source-grep-тестам («классы `duo`/`tiles--4`/media-блок присутствуют») — и
приехала на стенд с корнем `#cabinet-root{max-width:520px}`. Все десктопные
правила применялись корректно, но во вьюпорте 1860px контент занимал 488px:
ограничение сидело выше по дереву, и ни один греп его не ловил.

## Root cause

Итоговая ширина элемента — произведение всей цепочки предков, а не его
собственных правил. Греп подтверждает «правило написано», но не «правило
получило место». Потерянная итерация — ровно из-за приёмки по грепам.

## Solution

Диагноз поставлен замером в браузере — `console.table` по цепочке предков от
`.cab-screen` до `html` (`getBoundingClientRect().width`, `max-width`,
`display`, `padding` каждого предка). Таблица сразу показала: Tilda отдаёт
полные 1860px до самого низа, сужение — наше, на `#cabinet-root`.

## Prevention

- Правки раскладки принимать **только после замера computed-ширины в
  браузере** на целевом вьюпорте (дев-стенд или headless): ширина ключевого
  контейнера должна сойтись с макетом числом, а не наличием классов.
- При «десктоп выглядит как мобильный» первым делом мерить цепочку предков
  снизу вверх — искать, кто первым теряет ширину; гипотезы о собственных
  правилах элемента — потом.
- Source-grep-тесты оставить для регрессий структуры (классы/media-блок на
  месте), но не считать их приёмкой раскладки — см. также
  [mockup-media-query-transfer](mockup-media-query-transfer.md).
