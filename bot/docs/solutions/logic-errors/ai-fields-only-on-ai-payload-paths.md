# SB-семья писалась только путями с ai_payload

## Problem

Из шести путей завершения диалога SB-поля трейд-ина писали только колбэк
финализации и аварийный мост (из ai_payload) и сабмит анкеты (из формы).
Три дыры: таймаут кабинета, Логика Б 48ч, фолбэк n8n-сбоя — ai_payload там
не существует, а к данным бота (found_info кэша) пути не обращались.
Четвёртая дыра тоньше: при живом found_info фронт кабинета НЕ рендерит поля
трейд-ина (read-only «Ваш автомобиль», app.js ownOrTradeinFieldsHtml), в
CabinetForm остаются None, а push_form_to_bitrix пропускает None — сабмит
уносил кредитные поля и терял трейд-ин-подмножество (сделки 51503, 51511).
Состав push_form не логировался — оба ложных вывода разбора выросли из
этой слепой зоны.

## Solution (план 2026-09-08-001)

- Слот защёлки `evaluation_car` (payload_v2.register_evaluation) — данные
  машины переживают пересборку кэша, как evaluation_value.
- Точка 1: `build_ai_tradein_fields(ctx)` (main.py) из слотов — вызывается в
  final_sync_wrapper (закрывает таймаут кабинета и воронковые финализации),
  Логике Б и фолбэке; всегда через filter_cabinet_owned_fields (R34).
- Точка 2: снапшот-фолбэк в push_form_to_bitrix — None-поля трейд-ина
  добираются из found_info снапшота; ФОРМА ГЛАВНЕЕ (значение клиента не
  перетирается); пусто у обоих → ключ не появляется.
- На колбэке/мосту слоты — setdefault-фолбэк пустых ключей ai_payload
  (модель главнее).
- Наблюдаемость: `AI_TRADEIN_FIELDS` (пути из слотов) и `CABINET_UF_PUSH`
  (сабмит: форма/снапшот/профиль раздельно) — грепаются одним словом.
- Госномер: воронковый слот канонизируется перед хендофом
  (payload_v2.normalize_plate_input: гомоглифы, хвост RUS/РУС, регион
  2-значный 01-99 или 3-значный с ведущей 1/7/9). Полный путь диалога —
  зона инструмента оценки n8n.

## Урок

Точка записи, привязанная к одному источнику события (ai_payload), молча
теряет данные на всех остальных путях. Карту путей завершения проверять
воспроизведением, а не чтением кода: обобщение «сабмит пишет семью из формы»
опроверглось только стендом (фронт скрывает поля при живом found_info).
Состав каждого писателя CRM обязан логироваться грепаемой строкой.
