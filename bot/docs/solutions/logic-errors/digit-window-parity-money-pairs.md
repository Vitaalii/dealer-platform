# Паритет с digit-strip склеивает денежные пары в «номер»

## Problem

Критерий «извлечение находит всё, что is_valid_phone признаёт номером»
(план 2026-09-07-001) реализовывался окнами по цифро-группам: любое
непрерывное объединение групп, дающее 10–11 цифр, отдавалось валидатору.
Валидатор вычищает ВСЕ нецифры — поэтому соседние числа предметной области,
разделённые пробелом/запятой/дефисом, склеивались: «800 000, 30 000» →
80000030000 → 11 цифр, ведущая 8 → «телефон» +70000030000. Взнос+платёж и
пробег+цена — типовые пары каждого кредитного/трейд-ин диалога. Сырой
fallback «всё сообщение через is_valid_phone» пропускал тот же класс
независимо от окон.

Нашла n8n-сторона попутной проверкой семантики флага. Замер на живом архиве
(632 диалога, 1326 реплик клиента): 2 реальных ложных срабатывания —
«Е259РХ37 120000» и «Н864СМ37, 220000» (госномер+пробег через fallback).

## Solution

Действующий критерий (Р9, план 2026-09-07-002): извлекаются формы ЗАПИСИ
телефона, а не всё, что digit-strip признаёт номером. Обоснование владельца —
асимметрия последствий: пропущенный номер виден (сделка в ОЖИДАНИИ), ложно
пойманный невидим (недозвонимый номер у дилера). Три слоя в
payload_v2.extract_phone:

1. запятая — не разделитель кандидата вовсе; « - » (дефис в пробелах,
   диапазон) режет кандидата — в телефонной записи их не бывает;
2. мультигрупповое окно принимается только при телефонной разрядности —
   белый список `PHONE_GROUP_PATTERNS` (11; 1-10; 1-3-7; 1-3-3-4; 1-3-3-2-2;
   4-7; 4-3-4; 4-3-2-2; 10; 3-7; 3-3-4; 3-3-2-2). Пополнение — только вместе
   с тестом в tests/test_phone_extract.py;
3. сырой fallback убран: путь A (рефлекс ИИ-диалога) сознательно СТРОЖЕ
   пути C воронки (Д6 — в воронке всё сообщение и есть ответ на прямой
   вопрос о телефоне, контекст другой).

Слепая зона списка наблюдаема (Д4): кандидат с телефонной суммой цифр, но
нетелефонной разрядностью пишется в лог меткой `PHONE_PATTERN_MISS` с
session_id и кандидатом — данные для пополнения списка приходят сами.
Защёлка `phone_collected` ставится только при фактической записи номера
(возврат save_user_phone проверяется, Р10) — будущее ложное извлечение,
отбитое стражем, не переводит диалог в режим «финализируй» навсегда.

## Замер до/после

- Синтетика: 17 позитивов (все формы записи, включая инцидентную
  «8/980/555-28-17» и «число+номер подряд») — без потерь; 12 негативов
  класса склейки + 14 прежних негативов — ноль ложных.
- Живой архив: старый PHONE_RE — 135 уловов, паритетный механизм — 137
  (2 ложных), новый — 135 (все — телефоны; настоящих номеров, отсечённых
  списком, ноль).

## Граница критерия

Не извлекаются: номер, слитый с другой цифрой без разделителя (одна группа
длиннее 11 цифр); экзотические разрядности вне списка (видны по
PHONE_PATTERN_MISS); запятые/« - » внутри «номера». Путь C (воронка,
is_valid_phone по всему сообщению) шире пути A — это решение, не дефект.
