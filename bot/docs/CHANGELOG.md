# CHANGELOG.md: UnifiedBot

Все заметные изменения в этом проекте будут документироваться в данном файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/), а проект придерживается семантического версионирования.

## [3.2.0] - 2026-08-05 (Клиентский личный кабинет) — не выпущено, ветка `feat/client-cabinet`

Личный кабинет клиента: вход по индивидуальной ссылке с 4-значным кодом (голос или SMS через ProstoSMS), TOFU-привязка номера, анкета кредита/трейд-ина, передача заявки в Bitrix существующим путём конверсии. Подробности реализации — `docs/CABINET_HANDOFF.md`, требования и решения — `docs/plans/2026-07-31-001-feat-client-cabinet-plan.md`.

### 🚀 Added (Добавлено)
* **Семь таблиц кабинета** в `database.py` (`cabinet_tokens`, `cabinet_otp`, `cabinet_sessions`, `cabinet_profile`, `cabinet_form`, `consents`, `cabinet_events`) по конвенции v1.34 — `create_all` + идемпотентные DDL в `init_db()`. Частичные уникальные индексы: один активный токен на пользователя, одна запись OTP «в полёте» на токен.
* **`sms_gateway.py`:** ABC `SmsGateway` + `ProstoSmsGateway` (голос и SMS равноправно), единый классификатор ошибок (`transport` / `service` / `subscriber`) для circuit breaker и автофолбэка, маскирующий тип `Secret`, неблокирующая самопроверка баланса при старте.
* **`cabinet_service.py` / `cabinet_api.py`:** API `/cabinet/api/*` — токены, HMAC-коды, Bearer-сессии (40 мин скользящих / 12 ч абсолютных), лимиты, анкета с черновиками, передача заявки. Модули — строгие листья, зависимости приходят через `setup(...)`.
* **`log_masking.py`:** маскирование телефонов, кодов и токенов на хендлерах корневого логгера, включая traceback и `aiohttp.access`.
* **`otp_worker`** (каденция 30 с): страховочный автофолбэк голос→SMS, экспирация кодов, сигнал A дилеру, circuit breaker с half-open, передача заявок по таймауту и подбор незавершённых передач.
* **Фронт `widget-custom/cabinet-app/app.js`** — одностраничный IIFE: авторизация, равноправный выбор канала, анкета с автосохранением и видимым состоянием, пинг сессии. Инструкции: `docs/CABINET_TILDA_SETUP.md`, `docs/CABINET_PROMPT_NOTE.md`.
* **Интеграция с ботом:** выдача ссылки при AI handoff, `cabinet_url` / `cabinet_status` в `qualification_context`, правило «кабинет перезаписывает» (фильтр UF-полей после отправки анкеты), перепривязка токена и переотправка результата при склейке сделок.

### 🔄 Changed (Изменено)
* **`pending_sync` получил потолок попыток** (`PENDING_SYNC_MAX_ATTEMPTS`, дефолт 10): неуспешный реплей инкрементирует `attempts` на обоих путях отказа, по достижении порога строка переводится в `status='fatal'` с однократным алертом и хранится для ручного разбора.
* **`BitrixService.enqueue_failed_request`** получил `skip_debounce`, **`BitrixService._request`** — `enqueue_on_failure` (оба дефолта сохраняют поведение чат-пути). Кабинет ставит задачи мимо 30-секундного дебаунса и ровно один раз.
* **Реплей очереди** вынесен в `replay_pending_sync(session)` и изолирован собственным `try/except` в `sync_worker`.

### 🐞 Fixed (Исправлено)
* По итогам код-ревью (`docs/reviews/2026-08-04-client-cabinet-review.md`) устранены 17 из 18 находок, в том числе: `X-Cabinet-Token` в whitelist CORS (без него опрос статуса не работал бы в браузере), timezone-aware сравнения времени (иначе весь кабинет падал бы на PostgreSQL), маскирование traceback (утечка телефона и кода в лог), единственная постановка в `pending_sync` (иначе дубли комментариев в сделке), подбор незавершённых передач заявки после рестарта, дозаполнение `deal_id` для ссылок, выданных до появления сделки, изоляция обязанностей воркера, границы числовых полей анкеты, дедуп техалертов, обнаружение ротации `CABINET_HMAC_KEY`, гонки во фронте (двойная отправка кода, порядок записи черновика), экранирование HTML в алертах дилеру.

## [3.1.0] - 2026-06-11 (Multi-Channel + Web Widget)

Мажорный релиз. Добавлена полноценная многоканальная архитектура с поддержкой Telegram и кастомного веб-виджета.

### 🚀 Added (Добавлено)
* **Многоканальный транспортный слой:** Введён абстрактный базовый класс `BaseBotClient` (`base_client.py`). Реализованы три клиента: `MaxBotClient`, `TelegramBotClient` (`telegram_client.py`), `WebBotClient` (`web_client.py`). Роутер `get_client(channel)` выбирает транспорт по каналу сессии.
* **Telegram-канал:** Новый webhook-хэндлер `/tg_webhook` (`handle_tg_webhook`). Поддержка inline-кнопок, ReplyKeyboard для нативного сбора контакта, удаление кнопок через `editMessageReplyMarkup`. Deeplink через `/start PAYLOAD`.
* **Кастомный веб-виджет:** Файлы `widget-custom/widget.js` + `avatar.jpg` раздаются статически из Python. Канал `web` через `WebBotClient` с очередями `asyncio.Queue`.
* **SSE-транспорт (`/chat_stream/{session_id}`):** Server-Sent Events вместо polling. Keepalive-ping каждые 30 сек. Виджет использует `fetch + ReadableStream` (не `EventSource`).
* **Catalog Proxy:** Эндпоинты `/catalog/{dealer_code}` и `/catalog-colors` проксируют NocoDB без передачи токена в браузер.
* **CORS Middleware:** Добавлен `cors_middleware` для корректной работы веб-виджета с любого домена.
* **`send_dealer_alert`:** Вспомогательная функция для алертов дилерам — всегда через MAX, независимо от канала клиента.

### 🔄 Changed (Изменено)
* **`process_max_input` → `process_input`:** Функция переименована, добавлен параметр `channel: str = "max"`. Все три канала используют единое ядро бизнес-логики.
* **`max_user_id` → `platform_user_id`:** Колонка БД переименована. В коде локальный алиас `max_user_id = user_id` сохранён для совместимости внутри `send_smartbot_reply`.
* **`database.py`:** Добавлена колонка `channel` (VARCHAR, default `'max'`). `get_or_create_user` принимает параметр `channel`. Безопасные `ALTER TABLE` в `init_db()` для миграции существующих БД.
* **Farewell-текст для веб-канала:** Убрана фраза "перейдите на сайт" — клиент уже находится на сайте.
* **Текст "Другая модель" для веб-канала:** Заменён на инструкцию закрыть чат и перейти к другому авто, вместо ссылки на сайт.
* **`comm_type_td`:** Отдельное поле конфигурации дилера для веб-канала (`Communication_Type_TD`). Если не задано — наследуется от `comm_type`.
* **`reminder_worker` / `sync_worker`:** Добавлена проверка `get_client(channel).supports_reminders()` перед отправкой farewell и ремайндеров.
* **`inject_prices_and_capture_model`:** Поиск авто исправлен — `car_id[2:4] == model_id` И `car_id[4:6] == complectation_id` (ранее индексы были некорректны).

### 🐞 Fixed (Исправлено)
* **Промпт ИИ-агента (имена):** Добавлены правила обработки имён: транслитерация латиницы → кириллица, игнорирование значения `"Клиент"` и системных значений, обращение без имени при любых сомнениях.
* **`widget.js`:** Скрыта строка "Нажимая «Отправить», вы соглашаетесь с политикой конфиденциальности" через `display:none`.

## [2.1.8] - 2026-05-25 (Stability & Archive Completeness)

Фокус релиза: закрытие пробелов в архивации диалогов, устранение критических багов webhook-обработчика, защита от ложных срабатываний умного перехвата и оптимизация управления памятью.

### 🚀 Added (Добавлено)
* **Архивация Dialogflow-диалогов (DF Archive Patch):** Реализована прямая архивация всех сессий, завершённых на уровне Dialogflow (без передачи в n8n). В конце ветки B (`final_sync_wrapper`) добавлен вызов `upsert_dialogue_archive` с динамическим маппингом поля `Final_Status`: `"По телефону"`, `"В MAX"`, `"refuse"`, `"other_model"`, `"DF_Finalized"`.
* **Фильтр устаревших вебхуков:** Добавлена проверка поля `timestamp` входящего события MAX. Вебхуки, опоздавшие более чем на 60 секунд, игнорируются с записью в лог. Это устраняет ложные срабатывания от отложенных повторных попыток доставки событий.
* **Тайпинг-индикатор перед n8n:** Добавлена отправка статуса `TYPING_ON` непосредственно перед HTTP-запросом в n8n, создавая ощущение "живого" набора ответа ИИ-ассистентом.

### 🔄 Changed (Изменено)
* **Динамический текст запроса контакта:** Текст сообщения на интенте `10_Contact_Phone` теперь подбирается в зависимости от сценария: `"Для получения расчета..."` (кредит/трейдин/комбо), `"Для получения информации..."` (сток), `"Для получения консультации..."` (консультация).
* **Динамический текст таймаута:** Аналогично, сообщение таймаута 30 сек адаптировано под сценарий: `"Вы также можете получить расчет/информацию/консультацию онлайн"`.
* **Текст кнопок таймаута:** `"ПРОДОЛЖИТЬ В ЧАТЕ"` → `"ПРОДОЛЖИТЬ"`, `"НИЧЕГО НЕ НУЖНО"` → `"ОТМЕНА"`.
* **Тип ввода для диплинков (`input_type`):** Для события `bot_started` теперь явно устанавливается `input_type = "deeplink"` (ранее было `"text"`).
* **Дебаунс-таймер сокращён:** Буфер ожидания перед отправкой в n8n снижен с 15 до 10 секунд. Тайпинг-индикатор внутри буфера активируется через 3 секунды ожидания.
* **Таймаут `fetch_n8n_logs`:** Снижен с 15 до 10 секунд. Добавлена явная обработка ошибок с заглушкой `"no_n8n_data"` при недоступности эндпоинта логов.
* **`BITRIX_WEBHOOK_URL` вынесен в константу:** URL вебхука Битрикс24 вынесен в глобальную переменную при старте приложения. Убраны 4 дублирующих вызова `os.getenv()` внутри функций.
* **Тексты фолбэков ИИ:** Незначительная правка формулировок сообщений при технических сбоях n8n (убрано слово "возникли", добавлено обращение "Я к Вам вернусь").
* **Префикс ремайндеров:** К текстам обоих уровней напоминаний добавлена подпись `"👨‍💼 Александр:\n"` для визуальной консистентности с ответами ИИ-агента.
* **Текст перехвата возражений:** `"Переводим диалог на специалиста отдела продаж"` → `"Переводим диалог на специалиста"`.

### 🐞 Fixed (Исправлено)
* **Критический баг двойного `request.json()`:** Удалён дублирующий вызов `await request.json()` в `handle_max_webhook`. Первый вызов обращался к `obj` до его инициализации, вызывая `UnboundLocalError` и возврат статуса 500 на все входящие вебхуки.
* **Удалена дублирующая функция `fetch_n8n_logs_for_archive`:** Первое объявление функции (строка 621) содержало некорректный `timeout=5` (число вместо объекта `aiohttp.ClientTimeout`). Удалено в пользу корректной второй версии.
* **Фикс ложного запуска Smartbot при новом диплинке:** Перехват возражений (`Immediate Objection Intercept`) теперь не срабатывает для событий `bot_started`. Добавлена проверка `input_type != "deeplink"` в условие перехвата, исключающая ситуацию, когда повторный переход по диплинку (например, с другой моделью авто) воспринимался системой как текстовое возражение клиента.
* **Фикс курсора `nocodb_synced_index` в sync_worker:** Обновление курсора перенесено внутрь блока `if`, где происходит архивация. Ранее курсор обновлялся безусловно при каждом проходе воркера, из-за чего брошенные диалоги переставали попадать в архив после первого прохода.

### 🧹 Optimizations (Оптимизация памяти)
* **Очистка `USER_CONTEXT` после финализации:** После успешной архивации (через `finalize_transcript_archive` и DF-патч) запись пользователя удаляется из in-memory словаря `USER_CONTEXT.pop()`. Данные сохраняются в PostgreSQL; при повторном обращении контекст перезагружается из БД.
* **Обрезка `chat_history` при сохранении:** В `save_context_to_db` добавлена обрезка массива истории до последних 100 записей перед сериализацией в `context_json`. Полная стенограмма всегда доступна в Bitrix24 и NocoDB. Обрезка происходит на копии (`ctx.copy()`), не затрагивая in-memory объект.
* **Очистка `python_logs` в sync_worker:** После успешной отправки брошенного диалога в архив (Логика А) массив `python_logs` удаляется из контекста, исключая его накопление в БД для незавершённых сессий.

## [2.1.7] - 2026-05-20 (CRM Fallback & Engine Optimization)

### 🚀 Added (Добавлено)
* **Аварийный мост CRM (Fallback Bridge):** Механизм автоматического перехвата тегов `<function_calls>` внутри текста ответов ИИ. При сбое вебхука n8n, Python самостоятельно парсит payload, обновляет сделку/смарт-поля в Битрикс24 и закрывает сессию.
* **Режим работы «Manager»:** Новый сквозной тип дилера, отключающий выбор каналов связи на финальных шагах кнопочных сценариев и мгновенно перенаправляющий лид на ИИ-ассистента Александра.
* **Централизованный сбор логов:** Внедрена функция `log_session`, собирающая пошаговые логи выполнения Python-скрипта в `ctx['python_logs']` с последующей выгрузкой в NocoDB.
* **Интеграция системных логов n8n:** Добавлен метод `fetch_n8n_logs_for_archive` для автоматического подтягивания истории выполнения нод n8n с Dockhost напрямую в поле `logs` аналитического архива.

### 🔧 Fixed & Changed (Изменено и Исправлено)
* **UX Обезличивание:** Полный рефакторинг текстов интерфейса. Замена фраз сбора контактов на ультракраткий формат, изменение текста нативной кнопки на «Подтвердить», замена таймаут-кнопки на «ПРОДОЛЖИТЬ В ЧАТЕ».
* **Фикс дублирования в Sync Worker:** Добавлен флаг `is_finalized`, блокирующий повторную выгрузку брошенных диалогов воркером, если они уже были штатно закрыты со стороны ИИ.
* **Стабилизация ремайндеров:** Привязка 2-го ремайндера к жесткой временной метке `reminder_1_time` вместо плавающего времени последнего действия пользователя.
