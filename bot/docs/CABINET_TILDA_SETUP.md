# Личный кабинет: настройка страницы на Tilda

Инструкция по размещению клиентского личного кабинета (`widget-custom/cabinet-app/app.js`)
на сайте дилера, собранном на Tilda. Кабинет — одностраничное приложение: авторизация
(телефон → выбор канала → код) и анкета живут на одной странице со сменой экранов внутри.
Разные страницы Tilda использовать нельзя — при переходе терялись бы токен из фрагмента
URL и состояние формы.

## 1. Создание страницы

1. В проекте Tilda создайте новую страницу с адресом **`/cabinet`**
   (Настройки страницы → «Адрес страницы» → `cabinet`).
2. Страница должна открываться **только по HTTPS**. У Tilda с подключённым доменом
   HTTPS включён по умолчанию — проверьте, что нет открытия по `http://`.
3. Домен страницы обязан совпадать с `Website_URL` дилера в конфигурации бота —
   CORS-whitelist API кабинета собирается из `Website_URL`, и запросы с другого
   домена будут отклонены браузером.
4. В настройках страницы отключите индексацию, если Tilda это предлагает
   (скрипт дополнительно сам добавляет `<meta name="robots" content="noindex">`).

## 2. Один блок T123 (HTML-код)

Добавьте на страницу **один** блок «Другое → T123 (HTML-код)» и вставьте в него:

```html
<div id="cabinet-root"></div>
<script>
  // Базовый адрес API бота (домен, на котором развёрнут unifiedbot), без слэша в конце
  window.UNIFIEDBOT_URL = 'https://bot.example.ru';
</script>
<link rel="preconnect" href="https://bot.example.ru" crossorigin>
<script src="https://bot.example.ru/widget-custom/cabinet-app/Production/calc_engine.browser.js?v=<версия>"></script>
<script src="https://bot.example.ru/widget-custom/cabinet-app/Production/calc_model.js?v=<версия>"></script>
<script src="https://bot.example.ru/widget-custom/cabinet-app/Production/app.js?v=<версия>"></script>
```

Замените `https://bot.example.ru` на реальный домен бота (все вхождения), `<версия>` —
на значения из сборки (см. ниже).

**Порядок тегов обязателен**: движок расчёта (`calc_engine.browser.js`) → модель
(`calc_model.js`) → приложение (`app.js`). Порядок тегов — это порядок исполнения:
модель использует глобальные функции движка, приложение — модель. Если первые два
скрипта не загрузились, страница продолжает работать — блок калькулятора деградирует
в ручной ввод условий кредита.

**Подключается только сборка `Production/` (ускорение A2/A3, 2026-10-03).**
Исходники `widget-custom/cabinet-app/*.js` — с комментариями, для разработки и тестов.
Сборка — без комментариев, минифицированная, с заранее сжатыми копиями `.br`/`.gz`
(бот отдаёт их сам по `Accept-Encoding`): `app.js` 240 КБ → 100 КБ, по сети ≈ 23 КБ (br).

- Сборка: `npm install` (один раз), затем `npm run build:cabinet` — пересобирает
  `Production/`, пишет `Production/manifest.json` и печатает три строки `<script>`
  с актуальными `?v=`. `npm run check:cabinet` — проверка, что сборка не устарела
  (то же проверяет pytest `tests/test_cabinet_build.py` по хешам исходников).
- **Версия в адресе `?v=` — из сборки** (первые 10 символов sha256 файла сборки),
  не ручной счётчик. Бот отдаёт файл с `Cache-Control: public, max-age=31536000,
  immutable`, только если `?v=` совпадает с манифестом; иначе — `no-cache`
  (устаревший `?v=` на странице не закрепит старую копию на год).
- **При каждом деплое, где менялся любой из трёх файлов:** `npm run build:cabinet`,
  коммит `Production/`, затем на страницах `/cabinet` (бой) и `/cabinet_dev` (дев)
  заменить три строки `<script>` на выведенные сборкой и опубликовать страницы.
  Меняются только `?v=` изменённых файлов.
- `calc_engine.browser.js`: версия сборки не равна `CALC_ENGINE_VERSION` — константа
  по-прежнему внутри файла, расхождение движка и модели ловит автотест.

**Дев-страница `/cabinet_dev` (веб-вход, план 2026-09-30-001).** Дев-бот выдаёт
адреса кабинета на путь `/cabinet_dev` (env `CABINET_PAGE_PATH`), боевой — на
`/cabinet`. Страница `/cabinet_dev` на демо-сайте — тот же блок T123, скрипты и
`UNIFIEDBOT_URL` — с адреса дев-бота (ngrok), строки `<script>` — из той же сборки.
Адрес кабинета веб-входа несёт `?src=web` перед `#t=…` — страница не должна его вырезать.

Больше ничего на странице размещать не нужно: все экраны, стили и логику рендерит
`app.js` внутри контейнера `#cabinet-root`. Оформление средствами Tilda
(Zero-блоки, стандартные блоки с текстом и т.п.) для кабинета не используется.

## 3. Запрет сторонних скриптов — важно для безопасности

На странице `/cabinet` **нельзя размещать никакие сторонние скрипты**:
счётчики, пиксели, чаты, виджеты аналитики, а также глобальные скрипты проекта
Tilda, если они подключают внешние сервисы.

Причина: токен входа и токен сессии хранятся в `sessionStorage`, а любой скрипт,
выполняющийся на той же странице (same-origin), может его прочитать. Лишний
сторонний скрипт — это риск кражи токена. Украденный токен без OTP на привязанный
номер бесполезен, но Bearer-токен активной сессии даёт остаточное окно доступа,
поэтому поверхность нужно держать минимальной.

Проверьте также «Настройки сайта → Аналитика» и HTML-код, добавленный на весь
сайт: если счётчики подключены глобально, отключите их для страницы `/cabinet`.

## 4. Проверка

1. Откройте в чате персональную ссылку вида `https://<домен>/cabinet#t=...`.
2. Убедитесь, что фрагмент `#t=...` исчезает из адресной строки сразу после
   загрузки (токен перекладывается в `sessionStorage`).
3. Пройдите авторизацию: телефон → согласие → выбор способа (звонок / SMS) →
   код → анкета.
4. В DevTools → Network проверьте, что запросы `/cabinet/api/*` уходят на домен
   бота и не получают CORS-ошибок.
5. Перезагрузите страницу посреди заполнения анкеты — кабинет должен открыться
   снова без повторного ввода кода (пока жива сессия).

## 5. Частые проблемы

| Симптом | Причина |
|---|---|
| «Кабинет открывается по персональной ссылке из чата» | Открыт `/cabinet` без `#t=...` и без живой сессии — это норма для прямого захода |
| CORS-ошибки в консоли | Домен страницы не совпадает с `Website_URL` дилера или указан неверный `UNIFIEDBOT_URL` |
| Ссылка сразу «недействительна» | Токен истёк или отозван — новую ссылку выдаёт чат |
| Пустая страница | Блок T123 без `div id="cabinet-root"` или `app.js` не загрузился (проверьте URL скрипта) |
