## 3. На паузе — решение владельца, разведка готова

### 3.1. Замена входящего вебхука Битрикса (портал b24-mxici0)

Вебхук используется **только ботом** (n8n его не использует — проверено агентом n8n 07.10). Меняет владелец:
новый вебхук в Битриксе → `BITRIX_WEBHOOK_URL` в Dockhost → рестарт → проверка → отзыв старого.

**Права нового вебхука — только `crm`.** Вызовы по коду:
- `main.py`: `crm.deal.add/get/list/update`, `crm.contact.add/get/list/update`, `crm.timeline.comment.add`;
- `cabinet_service.py` (через бот): `crm.deal.update`, `crm.timeline.comment.add`;
- `scripts/bx_delete_test_deals.py`: `crm.deal.list/get/delete`, `crm.contact.get/delete`.

- Создать **от того же пользователя**, что и старый (`/rest/1/…`): вебхук работает с правами создателя
  (видимость сделок, удаление). `BITRIX_USER_ID` (ответственный) от этого не зависит.
- Адрес — **со слэшем в конце**, как его показывает Битрикс: `BitrixService` склеивает `f"{WEBHOOK}{method}"`
  (`main.py:591`); без слэша ломаются все вызовы.

**Проверка после рестарта, до отзыва старого:**
- Контрольный диалог в чате на сайте с новым телефоном до конца (передача → колбэк n8n). В логе:
  `🔄 [Bitrix] Starting request crm.contact.list` / `crm.deal.list` → `🔍 [Bitrix Response] …`;
  `✨ [Bitrix] New Deal Created: <id>` (или `✅ Found Bitrix deal`); `📥 N8N Callback received for Deal <id>` →
  `✅ Bitrix Deal <id> status updated in BACKGROUND.`; `✅ Bitrix Deal <id> comment updated with FINAL transcript.`
- По желанию — вход в кабинет с лендинга и анкета: `✨ [Bitrix] Web-entry deal created: <id>`, затем
  `crm.deal.update` и `crm.timeline.comment.add`.
- Стоп-признаки (старый не отзывать): `⚠️ [Bitrix Retry] Attempt …/3 failed for <метод>: API Error (Status 401)`,
  `❌ [Bitrix FATAL] Failed …`, `❌ Bitrix Webhook URL is missing!`, `❌ Фоновая отправка в Bitrix упала`;
  новые строки в `pending_sync` боевой `max_bot_db` после рестарта.
- Сделку контрольного диалога — в список на удаление (3.4).

**Дев:** в `.env` адрес **задан** (сейчас старый). Битрикс на деве выключается только префиксом команды запуска
`BITRIX_WEBHOOK_URL= … venv/bin/python -u main.py` (`CABINET_CONTEXT.md`, «Веб-вход с лендинга»): `load_dotenv()`
не перезаписывает уже заданную (даже пустую) переменную. Решение: **новый адрес — в `.env`** (на нём работает
`bx_delete_test_deals.py`), дев-бот запускать **только с префиксом `BITRIX_WEBHOOK_URL=`**; без префикса бот
включит Битрикс. Если `.env` не обновить до отзыва, дев-бот без префикса получит 401 и наполнит `pending_sync`
(нарушит чек-лист E). Вариант надёжнее (позже, правка скрипта): адрес в `~/.config/autodc/bitrix-webhook.secrets`,
в `.env` — пусто.

**Скан архива NocoDB после отзыва — только с разрешения владельца.** Таблица `mnivr6uyf5ckzru`. План: сначала
count (`limit=1`); если доступен серверный фильтр — `where=(<поле текста>,like,%/rest/%)`, `fields=Id`; иначе
страницы по 25, `fields=Id,<поле текста>`, пауза 1–2 с. В выводе — только Id и число совпадений. Признак утечки —
`bitrix24.ru/rest/<цифры>/<токен>` без маски `•••`; новый токен в архиве — сбой маскирования (`log_masking`).
