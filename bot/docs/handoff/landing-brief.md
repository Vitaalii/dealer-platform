## Поток

1. Клиент выбирает сценарий: кредит, трейд-ин или кредит + трейд-ин. Для кредита — платёж на шкале, для трейд-ина — госномер и пробег.
2. «Далее»: лендинг отправляет ту же форму Tilda, что сейчас, со значениями `offer` = «ЛК с сайта» и `form_type` по сценарию. Затем вызывает «открыть сессию» у бота.
3. Бот возвращает `cabinet_url`. Лендинг переходит по нему в той же вкладке.

## Контракт «открыть сессию»

`POST {BOT_URL}/cabinet/api/web/open`
Заголовки: `Content-Type: application/json`. Для дев-бота за ngrok добавить `ngrok-skip-browser-warning: 1` — бот разрешает его в CORS.
CORS: запрос принимается только с Origin из `Website_URL` дилеров. Чужой Origin получает `403 {"error": "forbidden_origin"}`.

### Тело запроса

| Поле | Обязательно | Формат |
|---|---|---|
| `dealer_code` | да | 2 цифры; совпадает с первыми двумя символами `lead_code` |
| `lead_code` | да | тот же код, что уходит в `sku-wa` формы Tilda: 6 цифр (дилер, модель, комплектация) + 4 случайные латинские буквы, например `991411QPXK` (`^\d{6}[A-Z]{4}$`, регистр бот приводит к верхнему) |
| `nonce` | да | случайная строка не меньше 128 бит, `^[A-Za-z0-9_-]{22,128}$` (например, 16 байт `crypto.getRandomValues` в base64url или hex); новая на каждую отправку формы, при повторе та же |
| `model_id`, `complectation_id` | да | «Model id» и «Complectation id» из `window.ucQuiz.selectedCar` (строки) |
| `scenario` | да | `credit` / `tradein` / `combo` |
| `desired_payment` | для `credit`, `combo` | целое, ₽/мес |
| `plate` | для `tradein`, `combo` | госномер после маски: буква, 3 цифры, 2 буквы, регион из 2–3 цифр; буквы АВЕКМНОРСТУХ, латиница-двойник допускается |
| `mileage` | для `tradein`, `combo` | целое 0…1 000 000; те же госномер и пробег — в скрытых полях формы Tilda `CAR_NUMBER` и `mileage` (интеграция пишет «Trade-in - номер», «Trade-in - пробег»; решение 2026-10-03) |
| `form` | да | блок полей формы Tilda — см. ниже |

Блока `car` больше нет: всё о машине бот берёт из каталога.

### Блок `form`

Объект «имя переменной формы Tilda → строка». В него входит:

- **все поля формы Tilda как есть** — те же значения, что уходят в форму. Имена — как в самой форме (`Model`, `modification`, `complectation`, `SKU`, `Link`, `Price_ac`, `Price_ol`, `BRAND`, `DEALER`, `FORMID`, `WEBSITE`, `LETTER_TITLE`, `messenger`, `color-select`, `BONUS`, `QUANTITY`, `sku-wa`, `offer`, `form_type` и т. д.). Регистр имени бот не учитывает (`Link` = `LINK`);
- **`FORMID`** — id своей формы Tilda. Его передаёт сама форма (строка вида `form2472574461`: это id блока формы на странице, `form` + recid). В сделках Tilda с demo сейчас встречаются `form2472574461` и `form2380472041`. По «Форме» робот стадии «Обогащение» в Битриксе выбирает адресатов письма о заявке, поэтому значение должно совпадать с тем, что Tilda шлёт в Битрикс для этой формы;
- **`LINK`** — «Вход в ЛК». Бот использует его только как запасной вариант, если в каталоге пусто, и только если это относительный путь или https-адрес на домене дилера;
- **UTM** из адреса страницы: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`;
- **cookies** — сырые значения, без добавления «;»: `_ct_session_id`, `_ym_uid`, `WhiteCallback_visit`.

Правила:
- только строки;
- нет значения — ключ не передаётся;
- не больше 80 ключей, имя до 64 символов, значение до 2 000 символов, весь блок до 16 КБ.

Нарушение даёт `422 invalid_input` с `fields.form`: `required`, `invalid` или `too_large`.

Бот хранит блок и использует его только тогда, когда сделка Tilda по коду не нашлась и бот создаёт свою. Её он заполняет по той же таблице соответствий, что интеграция Tilda. IP клиента бот берёт сам.

### Ответ

`200 {"cabinet_url": "https://<сайт дилера><путь кабинета>#t=<токен>"}`. Для дев-бота путь `/cabinet_dev`, для боевого — `/cabinet`. Переход — в той же вкладке.

Повтор с тем же `lead_code` и тем же `nonce` возвращает тот же адрес, в том числе после того, как клиент ввёл телефон. Лимит при этом не тратится, блок `form` не перезаписывается.

**Время жизни сессии.** Токен веб-сессии живёт 40 минут, пока клиент не подтвердил номер звонком. После подтверждения действует обычная сессия кабинета.

Повтор после 40 минут неподтверждённой сессии (тот же `lead_code` и `nonce`) **всегда открывает новую сессию** (решение владельца 2026-10-02): новый адрес, та же сделка, звонок заново, расходуется лимит открытий, как у нового открытия. Старый адрес не возвращается — иначе клиент попадал бы в цикл «Сессия завершена» → «Вернуться на сайт» → «Далее» → «Сессия завершена». Для лендинга ничего не меняется: ответ `200 {cabinet_url}`, переход по адресу.

### Ошибки

Тело ответа: `{"error": "<код>", ...}`.

| HTTP | `error` | Когда |
|---|---|---|
| 422 | `invalid_input` + `fields` | нет обязательного поля, неверный тип, формат или сценарий; `dealer_code` не совпадает с префиксом кода; блок `form` не прошёл проверку; тот же код с другим `nonce` (`fields.nonce = "mismatch"`) |
| 422 | `invalid_plate` | номер не проходит проверку формата |
| 404 | `unknown_dealer` / `unknown_position` | дилер или пара позиции не найдены, либо у позиции нет цены |
| 429 | `rate_limited` + `limit_source: ip \| dealer` | больше 5 открытий в час с одного IP, суточный лимит дилера исчерпан или веб-вход выключен |
| 403 | `forbidden_origin` | Origin не из `Website_URL` дилеров |
| 503 | `cabinet_unavailable` | у дилера нет https-сайта, каталог или ставки недоступны |

На любую ошибку, сетевой сбой или 15 с без ответа лендинг показывает: «кабинет открыть не удалось, попробуйте ещё раз или получите расчёт другим способом» — и предлагает перейти на «В чате» или «По телефону» (R9, макет `uc-calc-lk-states.html`).

## Настройки дилера: `GET {BOT_URL}/cabinet/api/dealer/{dealer_code}`

На сайте задаётся только код дилера — скрытое поле формы `dealer_id`. Всё остальное лендинг получает этим запросом. CORS такой же, как у «открыть сессию»: только с сайтов дилеров. Ответ кэшируется на 5 минут (`Cache-Control: public, max-age=300`).

`dealer_code` — 2 цифры. Ответ 200:

```json
{
  "dealer_code": "99",
  "dealer": {
    "Dealer_Code": "99", "Dealer_name": "Автомир Самара",
    "Dealer_address": "Самара, ул. Авроры, д. 150Е", "Dealer_location": "53.21, 50.18",
    "Dealer_workinghours": "пн-вс: 09:00-21:00", "Dealer_phone": "+7 (999) 555 5555",
    "Dealer_status": "Официальный дилер HAVAL"
  },
  "tables": {
    "catalog":  {"table_id": "mywf0f16ptn25gk", "active_field": "Active"},
    "features": {"table_id": "mm8wldgk5vn9gwh"},
    "rates":    {"table_id": "mfocbgvi50mqm7c"}

  "form_values": {
    "brand": "Haval", "dealer": "Автомир Самара", "website": "https://demo.autodc.org",
    "letter_title": "Тестовая заявка", "form_type": "ВЫБОР АВТО"

```

- `dealer` — те же 7 полей, что сейчас отдаёт `/catalog/muruk10ipof33m5` для карточки дилера, с теми же именами.
- `tables` — id таблиц для `/catalog/{table_id}`: каталог, оснащение, ставки.
- `tables.catalog.active_field` (бот 3.4.1, решение владельца 2026-10-06) — **колонка каталога, по которой
  этот дилер показывает позиции**: строку показывать, если в ней взведён флажок `row[active_field]`.
  Значение всегда есть: `"Active"` по умолчанию или `"Active_<число>"` из настройки дилера
  (Dealers.`Catalog_Active_Field`). Нужна для общих каталогов: каталог Geely `m2flt4d2r5d9cpa` общий
  у дилеров 02 и 09, у 02 — `"Active_1"` (15 позиций), у 09 — `"Active"` (20). Жёстко `Active` в коде
  лендинга не писать — брать из ответа. Если позиция вне колонки дилера всё же откроет сессию
  (устаревшая сборка), бот пропустит её и пришлёт техалерт.
- `form_values` — значения одноимённых скрытых полей формы Tilda. `form_type` — значение по умолчанию для вкладок «В чате» и «По телефону»; во вкладке «В личном кабинете» лендинг ставит своё значение по сценарию (L4).
- `cabinet_page_url` — адрес страницы кабинета ровно таким, каким начинается `cabinet_url` из «открыть сессию» (до `#t=…`): дев-бот — `…/cabinet_dev?src=web`, боевой — `…/cabinet?src=web`. Для prefetch страницы (L9) — дословно. Нет https-адреса сайта дилера — ключа нет.
- `cabinet_assets` — пути файлов кабинета на боте с текущей версией, ровно те же адреса, что в строках `<script>` страниц `/cabinet` и `/cabinet_dev` (L9). Нет сборки — ключа нет.
- Пустое значение в справочнике — ключа в ответе нет. Состав полей фиксирован; новые поля — только по решению владельца.

Ошибки: `422 invalid_input` (код не из двух цифр), `404 unknown_dealer`, `503 dealers_unavailable` (справочник ещё не загружен ботом — повторить запрос позже).

## Работы L1–L8

- **L1.** Третья вкладка «В личном кабинете» — первой. `calcOffer` получает третье значение во всех 4 местах. Классы — `uc-calc-*`. Таб-бар на мобильном — как в `uc-calc-lk-mockup.html`.
- **L2.** Сценарий, шкала платежа и поля трейд-ина:
  - границы шкалы считаются от «Price new»: минимум — взнос 90 % и 36 мес, максимум — взнос 30 % и 36 мес (решение владельца 2026-10-04; было 10 % и 12 мес); ставка — `Rate` строки `[brand]_Credit_Rates` с минимальным `Downpayment_From`;
  - шаг 5 000 ₽: минимум округляется вверх, максимум вниз до кратного 5 000; по умолчанию 30 000 ₽ с прижатием к границам;
  - ручной ввод платежа при уходе из поля приводится к ближайшему кратному 5 000 в пределах шкалы;
  - плитка «В КРЕДИТ» показывает минимум шкалы выбранной машины («Платеж от N ₽»);
  - госномер: поле не принимает недопустимые буквы, латиница-двойник заменяется на кириллицу; ошибка — только для неполного номера и только после ухода из поля, текст «Номер указан с ошибкой. Проверьте буквы, цифры и код региона.»;
  - пробег: только цифры, максимум 1 000 000 км.
- **L3.** «Далее» при пустом пробеге или неверном номере выглядит неактивной: не `disabled`, но `aria-disabled=true`. Подсказка связана через `aria-describedby` и показывается на десктопе по наведению и по фокусу с клавиатуры, на мобильном — по нажатию. После нажатия до ответа бота блокируются кнопка и вкладки; индикатор ожидания — только спиннер в кнопке.
- **L4.** Форма Tilda:
  - `offer` = «ЛК с сайта», `form_type` = «В кредит» / «В трейдин» / «Комбо», код с хвостом из 4 букв;
  - новый `nonce` на каждую отправку хранится **только в памяти страницы** (переменная JS), не в `sessionStorage`/`localStorage`; после перезагрузки страницы — новый код и новый `nonce`;
  - затем «открыть сессию» с ожиданием ответа не дольше 15 с;
  - в `fetch` «открыть сессию» указать `referrerPolicy: 'no-referrer-when-downgrade'`. Зачем: бот берёт из заголовка Referer адрес страницы лендинга для кнопки «Вернуться на сайт» на экранах «Сессия завершена» и «Слишком много попыток». По умолчанию браузер при запросе на чужой домен (бот, ngrok) отправляет только домен сайта — тогда кнопка ведёт на главную, а не на страницу автомобиля;
  - при повторе — тот же код и `nonce`, форма второй раз не отправляется;
  - переход в той же вкладке.
- **L4b.** (2026-10-03, ускорение — решение владельца) Форма Tilda и «открыть сессию» — **параллельно**, а не последовательно. Почему безопасно:
  - «открыть сессию» сделку Tilda не ждёт: поиск сделки при открытии — одна попытка с таймаутом 2,5 с, не нашлась — сессия открывается без неё; сделку по коду находит передача заявки из кабинета (через минуты), а не нашла — бот создаёт свою сделку из блока `form` (R61). Код и блок `form` у обоих запросов общие и известны до отправки;
  - повтор (тот же код и `nonce`) не меняется: бот отдаёт тот же адрес.
  Как делать:
  - по «Далее» запустить отправку формы Tilda и `POST /cabinet/api/web/open` одновременно;
  - **переходить по `cabinet_url` только после завершения отправки формы Tilda** (успех или ошибка) — уход со страницы обрывает запрос формы, и сделка Tilda не создастся;
  - ошибка формы Tilda при успешном «открыть сессию» — переход всё равно выполняется (сделку создаст бот); ошибка «открыть сессию» — сообщение L5, как сейчас; повтор после L5 — без повторной отправки формы, если она уже ушла;
  - ожидание 15 с (L5) — общее на оба запроса.
  Выигрыш — время формы Tilda (≈0,7 с на замере 2026-10-03).
- **L4a.** Возврат на страницу кнопкой «Назад» (событие `pageshow` с `persisted`) разблокирует кнопку и вкладки. Повторное «Далее» использует тот же код и `nonce`.
- **L5.** Сообщение об ошибке открытия кабинета (R9) — по макету `uc-calc-lk-states.html`. Показывается при любой ошибке бота, сетевом сбое и после 15 с без ответа. Фокус переходит на текст ошибки.
- **L6.** Тестовая страница `https://demo.autodc.org/page154296216` берёт каталог и открывает сессию у дев-бота (адрес ниже). Сейчас каталог она берёт у боевого бота.
- **L7.** Блок `form` в «открыть сессию»:
  - те же поля и значения, что уходят в форму Tilda, включая `FORMID`, UTM из адреса страницы и cookies `_ct_session_id`, `_ym_uid`, `WhiteCallback_visit` (сырые значения);
  - **`FORMID`** — id своей формы Tilda, как его передаёт сама форма в Битрикс. Проверить в Битриксе на тестовой отправке: поле «Форма» сделки Tilda должно совпасть с `form.FORMID`;
  - проверить на demo и на боевом лендинге, что три cookie читаются из JS (`document.cookie`, не HttpOnly), и записать результат. Если cookie недоступна, ключ не передаётся;
  - блок `car` не передаётся.
- **L8.** Настройки дилера с бота:
  - константы `DEALER_CODE`, `TABLE_MAIN`, `TABLE_FEATURES`, `TABLE_DEALERS` и другие `TABLE_*` убрать: код дилера брать из скрытого поля формы `dealer_id`, остальное — из ответа `GET /cabinet/api/dealer/{dealer_code}`;
  - таблицы каталога, оснащения и ставок читать через `/catalog/{table_id}` по id из `tables`;
  - позиции каталога фильтровать по колонке дилера `tables.catalog.active_field` (бот 3.4.1), а не по жёсткому `Active`;
  - ссылки на ботов во вкладке «В чате» (MAX, Telegram) — из `GET {BOT_URL}/bot-links` (решение владельца 2026-10-06, бот не меняется):
    ответ `{"bots":[{"channel":"max"|"telegram","brands":["haval",…],"link":"…"}]}`; марка дилера — `form_values.brand`
    в нижнем регистре; взять запись нужного канала, где марка есть в `brands`, и дописать к `link` start-параметр
    с кодом заявки, как сейчас. Зашитые в сборку ссылки ботов Geely убрать (на пилоте Haval «В чате» вёл в бота Geely);
  - карточку дилера брать из `dealer` вместо чтения таблицы Dealers;
  - при загрузке страницы вписывать `form_values` в одноимённые скрытые поля формы (`brand`, `dealer`, `website`, `letter_title`, `form_type`);
  - если запрос не удался — показать ошибку загрузки, как сейчас при сбое каталога.

- **L9.** (2026-10-03, ускорение — решение владельца) Заранее открыть соединение с ботом и загрузить файлы кабинета, пока клиент на шаге 2:
  - **когда:** один раз за загрузку страницы — когда на шаге 2 показана вкладка «В личном кабинете» (она первая) и пришёл ответ настроек дилера (L8); через `requestIdleCallback` (запасной вариант — `setTimeout(…, 1000)`); не во время прокрутки каталога на шаге 1;
  - `<link rel="preconnect" href="{BOT_URL}" crossorigin>` — для `fetch` «открыть сессию» (CORS-запрос);
  - `<link rel="preconnect" href="{BOT_URL}">` — для скриптов кабинета (обычные `<script>` без `crossorigin` идут отдельным соединением);
  - `<link rel="prefetch" href="{BOT_URL}{путь}" as="script">` — для каждого пути из `cabinet_assets` (L8), адрес — дословно, с `?v=`: только так браузер возьмёт файл из кэша на странице кабинета;
  - `<link rel="prefetch" href="{cabinet_page_url}" as="document">` — адрес из ответа настроек дилера дословно (с `?src=web`): браузер возьмёт страницу из prefetch только при точном совпадении адреса перехода без `#t=…`; HTML страницы кабинета с серверов Tilda — около 1,3 с на замере; нет `cabinet_page_url` — этот prefetch не делать;
  - нет `cabinet_assets` в ответе — prefetch файлов не делать (preconnect — делать);
  - `{BOT_URL}` — тот же адрес бота, что у «открыть сессию» (дев — ngrok, бой — домен бота).
