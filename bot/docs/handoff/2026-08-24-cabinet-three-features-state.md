# Фиксация сессии 2026-08-19…24: три задачи кабинета перед очисткой контекста

Ветка `feat/cabinet-calculator`, 25 коммитов не отправлены на origin, дерево
чистое, 510 тестов зелёные. Приёмка перепривязки пройдена владельцем на стенде
(повторный код не запрашивается, ссылка прежняя, машина и платёж новые).

## 1. Завершённые задачи

### Кликабельная ссылка кабинета (план `docs/plans/2026-08-19-001`)

Коммиты `ce691e2` (U1 бот), `e43d9f9` (U2 виджет), `f815255` (U3 доки),
`2ae7c47` (фиксы ревью), `50ba534` (residual-сток).

Поведение: Александр больше не печатает адрес кабинета — промпт ставит маркер
`[CABINET_LINK]`, бот в `send_smartbot_reply` подставляет `<a href>` с URL,
запрошенным read-only у `cabinet_service.get_active_cabinet_url` в момент
отправки (стэша нет, живой токен не персистируется). Тихая страховка
оборачивает точное вхождение сырого URL. История нормализуется маркер→URL во
всех 4 точках записи. Виджет рендерит строгую форму `<a>` (https-only,
`target=_blank rel=noopener`, палитра пузыря).

Промпты АКТУАЛЬНЫ (2026-08-24): три блока `BLK_*_CABINET_CHOSEN` в NocoDB
переведены на маркер `[CABINET_LINK]`, правило «после адреса не ставить
точку» удалено. Поверх применён пакет: требование про персональный доступ —
дословной фразой «Отлично! Кабинет персональный, доступ будет только у вас —
поэтому потребуется авторизация.» (модель в MAX пересказывала своими словами
и теряла аргумент). Приёмка: **веб-виджет и MAX приняты** (маркер
подставляется, литерала в чате нет, падежи верные); **остаётся Telegram и
проверка пересылки сообщений**.

### Чистый лист истории с момента передачи (план `docs/plans/2026-08-21-001`)

Коммиты `6541221` (U1+U2), `f57d8a4` (U3 доки).

Поведение: в момент AI handoff в `chat_history` пишется маркер границы
(`role=system, type=ai_handoff`, в ОБА объекта — снапшот и живой контекст,
с немедленным сохранением); `recent_history` для n8n собирается от последнего
маркера и без строк-кнопок (`type=button`, включая авто-нажатия бота
«ПО ТЕЛЕФОНУ») — на INIT пустая, дальше только диалог с Александром.
`msg_count`/стадии считаются по полной истории (иначе INIT давал бы greeting).
Архив нетронут; маркер виден в стенограммах. **Приёмка пройдена
(2026-08-24)**: первый ответ в MAX содержит расчёт и развилку, телефон не
просит, воронка в историю не попадает.

### Перепривязка сделки кабинета (план `docs/plans/2026-08-21-002`)

Коммиты `0aca636` (U1/U2/U4), `0ee688f` (U3 доки), `84f7460` (фиксы ревью).

Поведение: повторная квалификация у того же дилера перепривязывает active-токен
на новую сделку — URL и OTP-верификация сохраняются, живой сеанс не рвётся;
жизненный цикл заявки сбрасывается (анкета переезжает копией-черновиком со
сброшенным `submitted_at`, `handoff_at` обнулён, `bound_at`/`expires_at`
перезапущены, снапшот и `qualification_payment` — под новую заявку;
однократные события токена помечены старой сделкой — второй цикл передачи
полноценен). Триггеры: prepare (payload-пути) и ветка B (вернувшиеся
верифицированные — главная когорта). Деал-хант согласует
`active_deal_id`/`ctx` атомарным зеркальным гардом. **Приёмка пройдена.**

## 2. Действующие контракты

- **Маркер `[CABINET_LINK]`** — контракт с n8n в `docs/N8N_HANDOFF_CABINET.md`
  §5: адрес не печатать, маркер в месте ссылки, расширенная форма
  `[CABINET_LINK:анкор]` поддержана парсером но промптам не выдаётся,
  правило рерайта (`last_bot_message` несёт голый URL — не перепечатывать),
  «фраза-анкор без URL в истории = вероятный сбой доставки».
- **Отсечка истории** — §6 там же: `recent_history` начинается с последней
  границы передачи, пустая на INIT — норма, кнопки исключены; полная история
  только в архиве. Писатель маркера — `mark_ai_handoff` (main.py), читатель —
  `payload_v2.build_recent_history`; токен среза — `type=="ai_handoff"`.
- **Перепривязка токена, два флейвора** (`_rebind_token_to_deal`,
  cabinet_service): «склейка» (deal hunt — перенос как есть: submitted_at,
  pending_sync, переотправка) и «новая заявка» (сброс жизненного цикла, без
  переотправки/переписи pending). Вход `sync_cabinet_deal(user, dealer, deal,
  payment)`; гард от отката — события `deal_rebound` в окне
  `REBOUND_GUARD_WINDOW` (3 ч); `qualification_payment` теперь «первичная
  копия ПО ЗАЯВКЕ». Описание — CABINET_HANDOFF §4 (последние два буллета).

## 3. Принятые остатки этой сессии

- Recovery-воркер незакрытых сессий слеп к крэшу ВТОРОГО цикла передачи
  (`session_closed` ищется по типу события на токен; помеченная строка
  первого цикла удовлетворяет проверке). Окно узкое, основной путь закрытия
  работает.
- Кросс-дилерская повторная квалификация верифицированной когорты (ветка B)
  кабинет НЕ перепривязывает by design (fail-closed; смена дилера доступна
  только через prepare, недостижимый для клиентов с телефоном).
- Гард отката оконный: спустя 3 ч легитимно возвращённая сделка не
  блокируется; внутри окна откат по устаревшему ctx исключён.
- Полные списки остатков двух первых задач:
  `docs/residual-review-findings/2026-08-19-cabinet-link-clickable.md`
  (дублирование формулы derive, ссылка кабинета прежнего дилера при
  невалидном http-сайте нового, двойное экранирование расширенного анкора
  в web) и Риски планов 2026-08-21-001/-002.
