## Решения владельца продукта — закрыто, не переигрывать

- **Ж1. Клиренс — шестая плашка (вариант «б», с правкой бэка).** Поле есть в исходном
  каталоге и рисуется на лендинге дилера — кабинет не должен показывать меньше.
- **Ж2. Утилиты `mt-*` не переносим, отступы инлайновым style.** CSS-массив app.js
  заскоплен `#cabinet-root` поштучно — система утилит раздула бы его и завела вторую
  систему отступов рядом с существующей.
- **Ж3. Скелетон шапки авто убран.** Имя машины известно сразу из `/me` — кнопка видна
  с первого кадра без прыжка вёрстки; подсказка и кликабельность приходят с данными.
- **Ж4. Шапка (`.page-head` + `#cab-car-head` с попапом) — ВНУТРИ `#cab-content`.**
  После отправки бледнеет вместе с анкетой — осознанно. Рекомендация «вынести» отклонена;
  вместо этого в submitted кнопка явно некликабельна (див без обработчика, подсказки
  и шеврона), а открытый попап при переходе в submitted принудительно закрывается
  с возвратом фокуса на кнопку.
- **Ж5. Пустые данные:** имя пустое и данных нет → кнопки нет вовсе; объект без единого
  чипа и фото → ведём как `null` (некликабельно, попапа нет); имя пустое при живых
  данных → в кнопке «Выбранный автомобиль», подзаголовок попапа не выводится вовсе.
  Причина: не показывать пустую кнопку и попап из одного заголовка.
- **P2-1. Полного focus-trap нет.** Минимум: фокус на крестик при открытии, возврат
  на кнопку при закрытии, Escape закрывает — дёшево и покрывает основной кейс.
- **P2-2. Стрелки и превью галереи — нативные `<button>`.** Tab/Enter из коробки,
  никаких самописных key-хендлеров.
- **P2-3. Длинные имена — только CSS-эллипсис** (nowrap+ellipsis, max-width 360 на
  десктопе, 100% ширины на мобильном), JS-обрезки нет.
- **Область фото «Ваш автомобиль» — 356×200 (16:9), object-fit: cover.** Вариант
  323×200 (нативная 21:13, ноль обрезки) и переход на `contain` рассмотрены и
  отклонены владельцем: оставляем как есть.
- **Порядок мобильного блока «Ваш автомобиль» = десктопному** (U3c): фото → факты →
  «Фото модели…» → «Данные получены…»; прежний инвариант «мобильный пиксель в пиксель»
  для зоны подписей снят владельцем.

## Архитектурные инварианты сессии

- **Попапы ошибок (`#cab-popup`: конфликт 409, сетевая ошибка) монтируются в
  `document.body` — осознанно**: `setScreen` заменяет `root.innerHTML` целиком, попап
  обязан пережить смену экрана (реавторизация). Перенос внутрь `#cabinet-root` убьёт
  его при первой перерисовке. Стили узел получает **параллельными селекторами по id**
  (`#cabinet-root .popup, #cab-popup.popup {…}` и т.д. — без дублирования деклараций);
  scope-переменные `#cab-popup` — документированная копия корневых (менять синхронно;
  на html/body Tilda переменные не выносить — конфликт имён).
- **Попап авто, наоборот, живёт ВНУТРИ `#cab-car-head`** — им владеет `patchCarHead`
  вместе с кнопкой; патч единственный за жизнь экрана (`undefined` → объект/`null`),
  до данных кнопка некликабельна ⇒ открытый попап не может попасть под патч
  by construction. Попап-сиблинг вне `#cab-car-head` потребовал бы отдельного владельца
  рендера — не делать. Инвариант держится на том, что `applyMeResponse` всегда идёт
  через `setScreen`; «мягкое» обновление `/me` без setScreen сломает его молча.
- **Esc-подписка попапа авто** живёт на `document` только пока попап открыт,
  самоудаляется на мёртвом узле; `setScreen` снимает её единой воронкой
  (`closeCarPopup(false)` в начале). Переходы в submitted при живом экране всегда
  идут через `loadCabinet` — там снапшот открытости для возврата фокуса.
- **Сброс `state.car` при смене `calc.item_id`** в `applyMeResponse`: старый id
  читается ДО перезаписи `state.me`, иначе сравнение всегда «равно».
- **Новые media-правила — только в ХВОСТ media-блока**: страж
  `test_mobile_media_query_overrides_present` берёт `src.index('@media (max-width:600px)')`
  (первое вхождение литерала в исходнике!) и проверяет маркеры в первых 2500 символах.
  Вставка в начало/середину вытолкнет маркеры из окна; литерал `@media (max-width:600px)`
  нельзя писать в комментариях выше блока.
- **Литералы-стражи:** `class="own"` дословно (утилити-классы на этот элемент не
  вешать), id `cab-car-head`, подпись `OWN_PHOTO_CAPTION` дословно, «ровно один
  `fetch(`» (все запросы через `api()`), маркеры безсетевого блока U9.

## Инструкция проверки на боевой Tilda (после публикации и инкремента `?v=`)

1. Перезапустить локального бота (8080) — только тогда `/cabinet/api/car` начнёт
   отдавать клиренс; на живом стенде в попапе должно стать шесть плашек.
2. Открыть страницу кабинета, войти, DevTools → Console, выполнить:

   ```js
   var n=document.getElementById('cabinet-root'), bad=[];
   for(n=n.parentElement;n;n=n.parentElement){var cs=getComputedStyle(n);
     if(cs.transform!=='none'||cs.filter!=='none'||cs.willChange!=='auto'||
        cs.backdropFilter!=='none'||cs.perspective!=='none'||cs.contain!=='none')
       bad.push(n.tagName+'.'+n.className+' → '+cs.transform+' / '+cs.filter+' / '+cs.willChange);}
   bad
   ```

   **Норма: пустой массив `[]`.** Любая запись — предок `#cabinet-root`
   с `transform`/`filter`/`will-change` (типично для анимаций появления зеро-блоков
   Tilda): `position:fixed` попапа будет отсчитываться от этого предка, а не от
   вьюпорта.
3. Открыть попап кнопкой и проскроллить страницу. **Норма:** оверлей затемняет весь
   экран (включая шапку Tilda), диалог по центру (на телефоне — шторка прижата к низу
   экрана) и **неподвижен** при скролле. Если попап «едет» со страницей или встал не
   по экрану — сработал предок из п.2: отключить анимацию появления у блока с виджетом,
   либо фолбэк из плана (mount попапа авто в `document.body` с правилами по id, как
   у попапов ошибок — раздел «Проверка гипотезы», вариант 3).
4. Проверить, что фикс-элементы Tilda (шапка, кнопка чата) не всплывают поверх оверлея;
   если всплывают — поднять `z-index` попапа (сейчас 100).
5. Попапы ошибок теперь стилизованы (U4): при желании проверить — сабмит с выключенной
   сетью должен показать белый центрированный диалог «Не удалось отправить», а не голый
   текст внизу страницы.
