N8N_ARCHITECTURE.MD: Stateless AI Orchestrator
1. Роль n8n в архитектуре (High-Level Overview)
В данном проекте n8n выступает в роли Stateless AI Orchestrтора. Он не хранит в себе глобальных баз пользователей или настроек дилеров. Его главная задача — получить массивный контекст от Python-бэкенда (информацию о лиде, параметры поиска, токены доступа к таблицам), динамически подгрузить данные из внешних баз (NocoDB, Auto.ru), пропустить их через LLM-агентов с жестко заданными промптами и вернуть Python-боту готовый текст для отправки клиенту.

Глобальные зависимости:

LLM Провайдеры: Подключены через LangChain узлы (Gemini 2.5 Flash Lite и DeepSeek).

NocoDB: Выступает как Data Warehouse. n8n получает ID баз и таблиц динамически в каждом webhook-запросе, что делает воркфлоу универсальным для разных дилеров.

Auto.ru API: Используется для оценки Trade-In по госномеру.

2. Спецификация обмена данными (I/O API)

### 2.3 Системный эндпоинт логов исполнения (GET)
* **Endpoint:** `https://mgak-wacd-ospe.gw-1a.dockhost.net/webhook/get-session-logs`
* **Query Params:** `session_id={clean_session_id}` (принимает чистый ID сессии без префикса `sess_`).
* **Назначение:** Возвращает упорядоченный JSON-массив логов выполнения нод LangChain/DeepSeek для интеграции в тело архива NocoDB. Таймаут ответа со стороны Python-клиента жестко ограничен 15 секундами.

3. Главный Workflow (AI Agent v2.0)
Отвечает за маршрутизацию и управление контекстом.

3.1. Умное кэширование (Stateless Data)
Чтобы не делать тяжелые SQL-запросы в NocoDB на каждое сообщение клиента, реализован механизм cached_json:

На первом сообщении (cached_json пуст) n8n вызывает саб-воркфлоу Call 'Tool - Car Search', который делает запросы в NocoDB и собирает полный JSON автомобилей.

Перед передачей в ИИ-агента, нода Code in JavaScript обрезает лишние данные из кэша в зависимости от ветки (например, для кредита удаляются массивы features, images и stock_colors), чтобы сэкономить токены (Context Window) для LLM.

Очищенный JSON отдается агенту, а полный кэш возвращается в Python (json_cache).

На следующих сообщениях Python присылает cached_json обратно, и n8n пропускает этап опроса NocoDB.

3.2. Роутинг (Switch)
Нода Switch направляет диалог в одного из специализированных LangChain-агентов на основе переменной user_request.type:

credit: Ветка AI Credit.

stock / consult: Ветки AI Stock Search и AI Consult.

tradein: Ветка AI TradeIn.

combo: Ветка AI Combo.

3.3. LangChain Agents Config
Memory: Используется Window Buffer Memory (глубина 20 сообщений), привязанная к session_id. Память хранится во внутренней SQLite базе n8n.

Tools: Агентам доступны finalize_deal (для перевода на звонок) и специфичные утилиты (evaluate_auto, combo_calculator).

### 3.4. Системные триггеры (System Handoffs)
Python-бот может инициировать передачу управления ИИ-агенту без прямого текста от клиента, используя служебные команды:
* `__SYSTEM_TIMEOUT_HANDOFF__`: Вызывается, если клиент нажал кнопку продолжения диалога со специалистом или попытался обойти запрос телефона текстовым возражением.
* `__SYSTEM_REMINDER__`: Вызывается по таймеру (30 минут простоя). Служит сигналом для ИИ-агента взять строку `last_bot_message` и перефразировать её в короткое напоминание без использования приветствий и имен.

4. Sub-workflows (Инструменты ИИ)
Самая сложная часть архитектуры — математические модули внутри саб-воркфлоу.

4.1. TOOL: AUTO.RU EVALUATION
Оценивает авто по госномеру.

Гейткипер (Regex): На старте скрипт извлекает номер, очищает его и проверяет жестким Regex: /^[АВЕКМНОРСТУХABEKMHOPCTYX]\d{3}[АВЕКМНОРСТУХABEKMHOPCTYX]{2}\d{2,3}$/. Если номер кривой, отдает ИИ статус ERROR с просьбой запросить регион.

Запрос в Auto.ru: HTTP Request с Continue on Fail.

Обработка 404: Ошибки HTTP перехватываются, и боту мгновенно возвращается статус NOT_FOUND без запуска циклов ожидания (Wait).

IN_PROGRESS: Если авто.ру формирует отчет, возвращается инструкция для ИИ извиниться за задержку.

4.2. Tool - Car Search
Собирает каталог, сток и рассчитывает цены. Включает 5-уровневую систему ценообразования.

Иерархия цен (Aggregation Node):

MSRP: Базовая розничная цена.

cash_bonus: Прямая скидка от салона.

base_price: MSRP - cash_bonus.

credit_price: base_price - credit_bonus.

tradein_price: base_price - tradein_bonus.

Если клиент хочет только кредит, вызывается calculateCreditScenarios.

Алгоритм подбора ставки (getSmartRate):
Скрипт ищет ставку в массиве ratesList по сроку (term) и проценту первого взноса (downPct).

Строгий поиск: Точное попадание в вилки Term_From/To и Downpayment_From/To.

Мягкий поиск: Если точной вилки взноса нет, скрипт фильтрует ставки по сроку, сортирует их по Downpayment_From по возрастанию и берет первую доступную (например, берет ставку "от 10%", даже если у клиента взнос 40%, так как это самая выгодная из применимых).

Фолбэк: Если ставок в БД нет, подставляется 16% годовых.

4.3. Tool: Combo Calculator
Самый комплексный инструмент. Объединяет оценку Auto.ru и кредитную математику.

Инкапсуляция: Инструмент сам вызывает внутри себя Tool: Auto.ru Evaluation.

Блокировка ошибок: Если оценка вернула ошибку, скрипт обрывается и передает ошибку наружу (чтобы ИИ не галлюцинировал цифрами).

Комбо-цена: Вычисляет максимальную выгоду: finalComboPrice = basePrice - creditBonus - tradeinBonus.

> **Устарело (план 2026-09-30-001, R17).** База комбо — не «Price new»: `combo_price = round10k(Price old) − round10k(Cash in hook) − round10k(Credit bonus) − round10k(Trade-in bonus)`, как считает бот (`cabinet_service.compute_prices`). Правка ноды N5 у агента n8n; паритет проверяет `scripts/check_price_parity.py`.

Математика Комбо (calculateComboScenarios):

Принимает стоимость выкупа (tradeinValue) как жесткий первоначальный взнос.

Вычисляет тело кредита: Loan = finalComboPrice - tradeinValue.

Запускает цикл перебора сроков от 12 до Max_Term (с шагом 12 мес).

На каждой итерации получает ставку через getSmartRate и считает платеж (PMT).

Как только рассчитанный платеж становится меньше или равен желаемому платежу клиента (targetPayment), цикл останавливается. Клиенту предлагается самый короткий из возможных сроков.

Если даже на максимальный срок платеж выше желаемого, возвращается статус impossible.

4.4. TOOL: Save to CRM
Вызывается ИИ-агентом для завершения сделки.

Делает HTTP POST на вебхук Python-бота (/n8n_callback).

Отправляет user_id, deal_id и ai_payload со всеми собранными данными (от статуса visit/call до sb_brand и tradein_plate).

Настроен на Retry On Fail (до 5 попыток с интервалом 3 сек) для гарантии доставки лида.

⚠️ **Резервирование (Redundancy):** Если данный узел n8n падает по таймауту или сетевой ошибке, не успев сделать POST-запрос на `/n8n_callback` бэкенда, Python-бот активирует локальный аварийный мост (Fallback Bridge), считывая параметры сделки напрямую из текстового вывода LLM-модели, содержащего теги `<function_calls>`.
