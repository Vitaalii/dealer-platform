# feat: Перенос дизайна v3 личного кабинета на бой

## Сводка

Фронт кабинета (`widget-custom/cabinet-app/app.js`) переводится на внешний вид макета `docs/design/lk-source-v3.html`: карточка-товар авто в шапке с подзаголовком сценария, серые плашки-фразы вместо h2+lead, оценка «~ N ₽» внутри карточки «Ваш автомобиль», новая строка «Первоначальный взнос» в комбо. Функциональность заморожена (автосейв, валидация, CalcModel, состав полей, отправка); поведенческое изменение одно — карточка авто кликабельна после отправки (пересмотр правила Ж4); правка бэка одна — поле `price_new` в ответе `GET /cabinet/api/car` (решение В1).

## Решения владельца (приняты 2026-09-26)

Обоснования и механика — в разделах «Источник price new» (В1), «Оценка трейд-ина» (В3), «Состояния, которых нет в макете» (В2, В4, В5, В7, В9), «Изменение Ж4» (В8) и «Карта изменений» (В6).

- В1. **Цена «от N ₽»** — розничная цена из колонки каталога NocoDB `Price new`, через новое поле `price_new` в ответе `GET /cabinet/api/car` (минимальная правка бэка разрешена; остальные ключи ответа не меняются). `credit_price` не показывать.
- В2. **Неизвестный/пустой сценарий** — запасной вариант кода на сбой, в рабочем процессе не возникает (ссылка выдаётся только с известным сценарием): подзаголовок «Анкета», состав блоков как сейчас; отдельное оформление не прорабатывается, в чек-лист приёмки не входит, существующие тесты не ломать.
- В3. **Оценка трейд-ина** — в штатном трейд-ин/комбо-процессе `ti_valuation` заполнен (ссылку на кабинет Александр выдаёт только после оценки автомобиля). «~ N ₽» в карточке «Ваш автомобиль» и в строке зачёта комбо выводится из того же источника, что использует калькулятор (`me.calc.ti_valuation`). «Оценки нет» — редкий сбойный случай: ни суммы, ни пояснения.
- В4. **Трейд-ин без `found_info`** (редактируемые поля `tradein_*`) — запасной вариант кода на сбой: остаётся как есть, новое оформление не делается, в чек-лист не входит, существующие тесты не ломать.
- В5. **Комбо в деградации R18** — сохранить текущий состав (строка зачёта + доплата + три ручных поля), сменив только разметку строки.
- В6. **`FORM_LABELS.combo_extra_down`** — ключ удалить, страж-тест переписать на новую разметку.
- В7. **Кликабельность карточки** — появляется вместе с данными `/car` (как сейчас).
- В8. **Переход в submitted при открытом попапе** — попап закрывается, фокус возвращается на карточку, без переоткрытия.
- В9. **`no_credit_needed`** — строка «Зачёт + доплата» остаётся видимой (путь уменьшения доплаты обратно), вместо платежа/срока — прежняя строка «Кредит не требуется — зачёт покрывает стоимость»; плашка-фраза не меняется.
- В10. **Название авто в ответе `/car`** — `name` собирается как «Model · Complectation» (макет v3: «HAVAL M6 · Family»): заполнена одна часть — она выводится без точки, обе пустые — прежний фолбэк `Model title` → `item_name` снапшота. Причина: `Model title` каталога — комплектационный титул без модели («Tech+ 1.5T 150 л.с. AT 4WD»), заголовком карточки не годится. Это правка сверх первоначальной формулировки R16 (та обещала `name` не менять); принята 2026-09-26 по ходу U4, реализована коммитом `38c4501`.

Правки ревью 2026-09-26 приняты и внесены в требования и шаги: обязательные атрибуты нового поля доплаты (`data-key`, `inputmode`, класс `money__input`), единая точка сборки обёртки «Условия кредита», `aria-label` карточки авто.

- R2. Плашка авто становится карточкой-товаром: миниатюра фото (`images[0]` из `/car`), название, строка «от <цена> ₽» из нового поля `price_new` ответа `/car` (нет значения → строки нет), шеврон ›. ## Ключевые технические решения

- **KTD1. Строка взноса комбо не входит в пересобираемый узел.** Комментарии `app.js:2448-2451` фиксируют: `combo_extra_down` живёт вне `#cab-credit-block`, потому что блок пересобирается через `outerHTML` при флипе `no_credit_needed ⇄ ok`. Чтобы визуально попасть в макет (строка внутри «Условий кредита»), а функционально не сломать дебаунс/фокус/обработчик: общая обёртка `cab-group` держит заголовок «Условия кредита» + строку взноса + внутренний узел `#cab-credit-block` (платёж и срок); `outerHTML`-пересборка сужается до внутреннего узла. Обработчик доплаты остаётся навешенным один раз в `wireCreditBlock` — двойного навешивания и потери поля при флипе нет by construction. Обёртка с заголовком строится в одной точке для обоих сценариев с кредит-блоком — кредита и комбо (в трейд-ине кредит-блока нет, кадр 4b); строка взноса добавляется в обёртку только в комбо.
- **KTD2. Узел попапа выносится из `#cab-content`.** После отмены Ж4 попап должен открываться в submitted, но он рендерится внутри `#cab-content.readonly` (`opacity:.55` красит `position:fixed`-потомка и создаёт stacking context). Узел переезжает сиблингом `#cab-content` внутри `.cab-screen`: остаётся под сносом `setScreen` (`root.innerHTML`), Esc-механика не меняется; `patchCarHead` обновляет два узла (кнопку в шапке и попап в корне экрана).
- **KTD3. Строка цены в карточке — опциональный элемент.** Источник — `price_new` из `/car` (В1). Нет значения (`null`, каталог недоступен, `/car` ещё летит) → строка не рендерится, карточка сжимается.
- **KTD4. Плашки-фразы — один новый CSS-класс** (рабочее имя `.cab-phrase`) по `.s35` макета (фон `--field`, радиус 8, 20px 24px, 17px/500) с мобильным переопределением по `.s138` (16px 18px, 16px) в хвосте media-блока.
- **KTD5. `scenarioLeadHtml` расформировывается**: подзаголовок уходит в шапку (`showCabinetScreen`), фразы — плашками в `buildFormBlocksHtml` по месту блоков; фолбэк «Анкета» переезжает в подзаголовок (В2).
- **KTD6. Ж4-инверсия минимальна**: `interactive = hasContent` (условие `!state.submitted` убирается из `carHeadHtml:1879`); ветка `carPopupWasOpenBeforeReload` упрощается до унифицированного возврата фокуса на кнопку (В8); ветка «некликабельный див» и CSS `.car-pick--static` остаются только для Ж5-состояний без данных.
- **KTD7. Брейкпоинт остаётся 600px** — media-блок макета v3 (`lk-source-v3.html:348`) использует `max-width:600px`, совпадает с текущим (урок `docs/solutions/frontend-issues/mockup-media-query-transfer.md`: брейкпоинт сверен с источником, не унаследован вслепую).
- **KTD8. Минимальная правка бэка ради цены.** `get_car_card` уже читает живую строку каталога NocoDB для specs/фото — добавляется один ключ `price_new` из колонки `Price new` того же ряда. Форма ключей `{specs, images}` не меняется, `name` — по В10 («Model · Complectation»); фронт работает и со старым ответом (строка цены опциональна, KTD3) — порядок выката бэка и фронта свободный.

## 2. Источник price new (В1 — решено)

Решение владельца: цена в карточке — розничная, из колонки каталога NocoDB `Price new`; `credit_price` не показывается. Разрешена минимальная правка бэка: одно новое поле в ответе `GET /cabinet/api/car`, остальные ключи не меняются.

Факты (проверено 2026-09-26 по живой NocoDB и коду):

- Колонка называется дословно **`Price new`** (каталожная таблица дилера — колонка «Sourse table id» в Dealers; у демо-дилера это `mywf0f16ptn25gk`). Формат — целое число рублей (пример: `2849000`). Рядом есть `Price old` — не используется.
- `get_car_card` (`cabinet_service.py:3336-3407`) уже читает живую строку этого каталога по паре (Model id, Complectation id) снапшота — данные для цены под рукой, отдельный запрос не нужен.
- Расчёт кредита не затрагивается: калькулятор продолжает считать по `me.calc.price` (= `credit_price` из n8n-кэша, `cabinet_service.py:3189`); цена карточки и цена расчёта — разные величины из разных источников, фронт их не смешивает.
- Иерархия цен n8n для справки (`docs/N8N_ARCHITECTURE.md:118`): `MSRP` → `base_price` → `credit_price`/`tradein_price`; `Price new` каталога — розничный прайс позиции, в n8n-кэш он не входит.

Механика (KTD8, R16):

- Бэк: в ответ `get_car_card` добавляется ключ `price_new` — число из колонки `Price new` с валидацией по образцу `_calc_num` (`cabinet_service.py:2941`); пустое/невалидное значение → `null`. Ключи `{specs, images}` и ветки 404 `no_snapshot`/`not_found`, 503 `catalog_unavailable` не меняются; `name` — «Model · Complectation» (В10).
- Фронт: `carHeadHtml` рендерит строку «от <`formatMoney(price_new)`>» только при числовом `price_new > 0` (KTD3); нет значения или `/car` ещё не ответил — строки нет (до данных карточка и так некликабельна, В7).

Тесты бэка (`tests/test_cabinet_calc_data.py`, шаг U9):

- колонка заполнена числом → `price_new` в ответе как число;
- колонка пуста → `price_new: null`; нечисловое значение → `price_new: null`;
- остальные ключи ответа не изменились (существующий `test_car_card_specs_and_normalized_images` (:571) остаётся зелёным);
- ветки 404/503 без изменений;
- `name` = «Model · Complectation» при двух заполненных частях; одна часть — без точки; обе пустые — фолбэк `Model title` → `item_name` (В10).

## 3. Оценка трейд-ина (`ti_valuation`): источник и диагностика (В3)

Утверждение ранних версий плана «на проде `ti_valuation` всегда null» было неверным — оно опиралось на устаревший комментарий бэка. Цепочка по коду (проверена 2026-09-26):

1. **n8n (v3-пайплайн)**: воркфлоу оценки Auto.ru кладёт результат в блок `tradein_evaluation {status, estimated_value, found_info}` (`N8N/Alex_refactoring/flow/lib/combo_prepare.js:203-212`), Final Response переносит его в `json_cache.ti_valuation` / `json_cache.found_info`; ключи появляются **только когда оценка реально была** (тесты пайплайна `flow/lib/v3_pipeline_sim.test.mjs:740, 837-917`).
2. **Бот**: `_freeze_calc_snapshot` копирует `n8n_cache.ti_valuation` / `found_info` в снапшот как есть (`cabinet_service.py:3227-3232, 3247-3248`). Комментарий рядом («сейчас n8n их не кладёт — блокер n8n», `:3227-3229`) устарел — обновляется попутно в U9.
3. **`/cabinet/api/me`**: `ti_valuation` входит в allowlist `CALC_PAYLOAD_KEYS` (`:3298-3303`) → `me.calc.ti_valuation`.
4. **Фронт**: `CalcModel.initState` включает комбо-режим ровно при `ti_valuation > 0` (`calc_model.js:375-385`); сумма зачёта, которую клиент видит в калькуляторе, — это `me.calc.ti_valuation` (`comboReadoutHtml`, `app.js:2470-2471`, значение из `buildFormBlocksHtml:2552`).

Итог (В3): наблюдение владельца объясняется — раз комбо-режим на бою работает и показывает зачёт, `ti_valuation` на этих сделках заполнен. Обе новые точки вывода «~ N ₽» (карточка «Ваш автомобиль» и строка зачёта) читают `me.calc.ti_valuation` — тот же источник, что калькулятор; рассинхрон невозможен by construction. «Оценки нет» — редкий сбойный случай (оценка не проводилась или не доехала): в карточке строки оценки и пояснения нет, в строке зачёта — «—».

Почему план ошибался: (а) устаревший комментарий `cabinet_service.py:3227-3229`; (б) все 9 дев-снапшотов в `data/max_database_v2.db` содержат `ti_valuation: null` — дев-диалоги шли без оценки Auto.ru.

Проверка на боевых данных: прод-БД (PostgreSQL на Dockhost) с этой машины недоступна — `DATABASE_URL` живёт только в окружении Dockhost. Перед приёмкой (U7) выполнить в консоли Dockhost и сверить 2–3 свежие комбо-сделки с тем, что видит клиент:

```sql
SELECT user_id, dealer_code, calc_frozen_at,
       calc_snapshot::json->>'ti_valuation' AS ti_valuation,
       calc_snapshot::json->>'item_name'    AS item_name,
       calc_snapshot::json->>'price'        AS price
FROM cabinet_profile
WHERE calc_snapshot IS NOT NULL
ORDER BY calc_frozen_at DESC
LIMIT 10;
```

Ожидание: у свежих трейд-ин/комбо-сделок `ti_valuation` — число (у кредитных — null); значения совпадают с суммой зачёта в кабинете тех же пользователей.

## 4. Состояния, которых нет в макете

По каждому — как будет выглядеть (решения В2–В9 приняты 2026-09-26).

1. **Нет `ti_valuation`** — редкий сбойный случай (штатный трейд-ин/комбо приходит с оценкой, раздел «Оценка трейд-ина»). Карточка «Ваш автомобиль»: строки оценки и пояснения нет, карточка заканчивается подписями. Комбо, строка взноса: «Зачёт вашего автомобиля» + «—» (без «~»), поле доплаты и подпись на месте, `combo_extra_down` работает как обычный инпут (гард `mode === 'combo'` сохраняется, `app.js:2732-2733`). Отдельного пункта чек-листа нет.
2. **Нет `found_info`** (редактируемые `tradein_*` вместо карточки) — В4: запасной вариант кода на сбой, в рабочем сценарии не возникает (ссылку Александр выдаёт после оценки). Остаётся как есть: редактируемые поля, оценка не выводится, новое оформление не делается, в чек-лист не входит, существующие тесты этого варианта не трогать.
3. **Комбо, `no_credit_needed`** — В9. Обёртка «Условия кредита»: заголовок + строка взноса (зачёт «~ N ₽» + доплата, редактируемая — путь уменьшения доплаты обратно) + вместо платежа/срока прежняя строка «Кредит не требуется — зачёт покрывает стоимость». Плашка-фраза комбо остаётся без изменений.
4. **Деградация R18** (calc null / движок не подключён / engine_mismatch). Кредит: «Условия кредита» с тремя обычными полями (как сейчас), плашки и карточка авто на месте (цена карточки из `/car` живёт своей жизнью — KTD3). Комбо — В5: строка взноса (зачёт + доплата как обычный инпут в новой разметке) + три ручных поля; смысловой дубль «взнос» существует и сейчас — сохраняем, меняется только разметка.
5. **Карточка авто, деградации Ж5.** Без фото (`/car` летит, 404, пустой `images`) — миниатюра-плейсхолдер (серая заливка, как `own__empty`); без имени — «Выбранный автомобиль» (текущее Ж5); нет `price_new` — строки цены нет (KTD3); данных для попапа нет (ни чипов, ни фото) — карточка некликабельна, без шеврона (текущее Ж5-правило, вид «статичная карточка»); ни имени, ни данных — блока нет (Ж5). Кликабельность появляется вместе с данными `/car` — В7 (сохраняет инвариант `app.js:1827-1830` «открытый попап не попадает под patchCarHead»).
6. **Неизвестный/пустой сценарий** — В2: запасной вариант кода на сбой, в рабочем процессе не возникает. Минимально рабочий вид: подзаголовок «Анкета», состав блоков как сейчас (полный набор; плашки и строка взноса появляются вместе со своими блоками общей логикой, `app.js:2553-2559`). Отдельное оформление не прорабатывается, в чек-лист не входит, существующие тесты не ломать.
7. **Read-only после отправки** (все три сценария). Баннер сверху; `#cab-content.readonly` (`opacity:.55`) бледнит шапку с карточкой, плашки и форму; поля disabled, включая доплату; кнопки «Отправить» и савбара нет. Карточка авто кликабельна (R10): попап открывается поверх, непрозрачный (KTD2), Esc и крестик работают, фокус возвращается на карточку.

- Ж4-инверсия: `interactive` не содержит `!state.submitted`; узел попапа монтируется вне `#cab-content`.
- Формат «~ N ₽» в карточке «Ваш автомобиль» и строке зачёта; «—» при null.
- KTD1-инвариант: `#cab-credit-block` — внутренний узел, строка взноса вне пересобираемого фрагмента; обработчик доплаты навешивается один раз (`wireCreditBlock`).
- Атрибуты поля доплаты в новой разметке: `data-key="combo_extra_down"`, `inputmode="numeric"`, класс `money__input` (P1 ревью: без `data-key` автосейв умирает молча, ни один существующий страж не ловит).
- Заголовок «Условия кредита» присутствует в разметке кредита и комбо и живёт вне пересобираемого узла.
- Порядок блоков комбо: «Ваш автомобиль» раньше «Условия кредита».
- Бэк (`tests/test_cabinet_calc_data.py`): `price_new` — число / null при пустой или нечисловой колонке; остальные ключи ответа `/car` без изменений (детально — в разделе «Источник price new»).

### Чек-лист ручной приёмки (глазами)

Матрица: десктоп (~1280px) и мобильный (≤600px, реальный вьюпорт) × кредит / трейд-ин / комбо × до и после отправки. На каждый прогон:

1. Шапка: подзаголовок сценария; карточка — фото, имя, «от … ₽», шеврон; на мобильном карточка полноширинной строкой под заголовком.
2. Клик по карточке: попап (десктоп — центр, мобильный — шторка с грабером); Esc и крестик закрывают, фокус возвращается на карточку.
3. Плашки-фразы: место (кредит — перед личными плитками; трейд-ин/комбо — перед «Общее техническое состояние»), размер 17px/16px, текст дословно.
4. Трейд-ин/комбо: оценка «~ N ₽» и пояснение внутри серой карточки над разделителем (при тестовом `ti_valuation`); без оценки — карточка без строки.
5. Комбо: порядок блоков; строка взноса (зачёт + «+ доплата»); набор доплаты не теряет фокус и значение при флипе `no_credit_needed ⇄ ok` (довести зачёт+доплату до цены и обратно); подпись под строкой; ввести доплату → перезагрузить страницу → значение сохранилось (автосейв через `data-key`).
6. После отправки: баннер, всё бледное, поля мертвы, карточка кликабельна, попап непрозрачный.
7. Деградация R18 (открыть кабинет без тегов движка/модели): три ручных поля, плашки на месте, комбо по В5.
8. Замер computed-геометрии предков `#cabinet-root` на реальной Tilda-странице (урок `docs/solutions/frontend-issues/css-width-verify-in-browser.md`) — грепы не заменяют браузер.
9. Узкий мобильный вьюпорт 320px: строка «зачёт + доплата» и карточка авто — без горизонтального переполнения и обрезки сумм.

Запасные варианты (неизвестный сценарий, `tradein_*` без `found_info`) в чек-лист не входят — В2/В4.

## 7. Выкладка

Текущее состояние (проверено на живом проде, см. «Контекст»): `Cache-Control: no-cache` + ETag/304 на `/widget-custom/*.js` уже стоят; Tilda-страница уже подключает `app.js?v=6`. То есть механика доставки готова, «переходного периода без кеш-дисциплины» нет.

**Расхождение дока, зафиксировано 2026-09-28:** в сниппете `docs/CABINET_TILDA_SETUP.md` стоит `app.js?v=2`, а на живой Tilda-странице — `?v=6`. Разрыв достался до этой задачи (док отставал от страниц и ни один страж его не ловит: `TestU10TildaThreeScripts` пинит наличие и порядок трёх тегов и сверяет только версию движка, целочисленную версию `app.js` — нет). Ветка `feat/cabinet-v3-redesign` док не меняла. Вывод для U8: в доке ставится **`?v=7`** — то же значение, что уходит на Tilda-страницы, а не инкремент от 2 (иначе док разойдётся с боем снова).

Порядок выката (по образцу `docs/handoff/2026-09-23-multibot-prod-release-runbook.md`):

1. Собрать новый образ с новым тегом `multy-vX.Y.Z` (старые теги не перезаписывать — это точки отката); проверить состав образа до push (новый `app.js` внутри). Правка бэка `cabinet_service.py` (`price_new`, U9) едет в том же образе — отдельный деплой не нужен.
2. Сменить образ на Dockhost; сразу `curl` живого `app.js` — сверить с рабочей папкой (это же — критерий отката).
3. Инкрементировать `?v=` у `app.js` (6 → 7) на Tilda-страницах кабинета всех дилеров, где страница создана (сейчас — `demo.autodc.org/cabinet`); `calc_model.js?v=1` и `calc_engine.browser.js?v=2026-08-06.1` не трогать — файлы не меняются.
4. Обновить `docs/CABINET_TILDA_SETUP.md`: в сниппете поставить `app.js?v=7` (сейчас там `?v=2` — см. «Расхождение дока» выше; равняем док на фактическое значение страниц, а не инкрементируем от 2). Стражи `TestU10TildaThreeScripts` (`tests/test_cabinet_frontend.py:798`) следят за форматом тегов, но не за целым числом `app.js` — сверять глазами.
5. Живая приёмка — только после инкремента `?v=` и жёсткого обновления (урок `config-pickup-delay-live-check`: «проверил — увидел старое» здесь даёт браузерный кеш, для `no-cache`-файла достаточно обычной перезагрузки, для CDN Tilda — `?v=`).
6. Любое расхождение — откат на предыдущий тег образа и возврат `?v=6`.
