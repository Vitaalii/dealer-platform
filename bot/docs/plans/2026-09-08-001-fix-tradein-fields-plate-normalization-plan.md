## Key Technical Decisions

- **KTD-12 (пересмотрен по Н5, сделка 51503): «в момент завершения», ДВЕ
  точки.** «По ходу» отклонено (лишние вызовы Bitrix, промежуточные значения,
  переезд сделки при deal hunt). Точка 1 — хелпер из слотов защёлки в
  final_sync_wrapper: закрывает таймаут кабинета, Логику Б, фолбэк n8n-сбоя
  и воронковые финализации; R34-фильтр обязателен и НЕ мешает (на этих путях
  submitted_at нет). Точка 2 — снапшот-фолбэк в push_form_to_bitrix: для
  FORM_FIELDS-ключей трейд-ина с None значение берётся из found_info снапшота
  (данные там подтверждены [live]: steering/оценка из него же записались);
  форма главнее — non-None значение клиента не перетирается. Одной точкой
  сабмит-путь закрыть нельзя: R34 исключает SB-ключи хелпера ДО push_form.
- **KTD-17 (наблюдаемость, Н1):** push_form_to_bitrix логирует состав
  uf_fields перед отправкой (одной строкой, грепается) — слепая зона, из-за
  которой состав второго писателя не был виден в логах.
- **KTD-13 (источник — защёлка, не кэш):** по образцу evaluation_value
  (80c6925) защёлка расширяется слотом `evaluation_car`
  {make, model, year, mileage, plate} из found_info при register_evaluation —
  переживает пересборку кэша; снятие защёлки чистит слот.
- **KTD-14 (приоритет ai_payload):** на колбэке/мосту значения модели из
  ai_payload остаются главными (модель может знать больше — год, уточнённый
  пробег); слоты — фолбэк для пустых ключей. В final_sync-точке слоты —
  единственный источник.
- **KTD-15 (R34 обязателен):** любая новая точка записи SB-ключей проходит
  filter_cabinet_owned_fields — после сабмита анкеты кабинет владеет полями.
- **KTD-16 (блок 2, наша зона — слот воронки):** нормализация воронкового
  ввода перед хендофом (расширение normalize_plate: RUS/РУС-хвост, регион по
  списку) — Александр не стартует с мусорного номера. Полный путь диалога
  закрывает только инструмент (зона второго агента) — см. раздел n8n.

## Второму агенту (n8n) — точная формулировка

Зона: саб-воркфлоу TOOL_ AUTO.RU EVALUATION, узел «Забираем номер» (jsCode,
cleanPlate/plateRegex). Требование:

1. **Хвост региона-страны:** после strip/upper отрезать завершающие RUS/РУС/RU
   перед валидацией. Кейс: «T582XP 33 rus» → сейчас «T582XP33RUS» → is_valid
   false → клиент потерян после двух слепых переспросов.
2. **Гомоглифы:** привести латиницу к кириллице (ABEKMHOPCTYX→АВЕКМНОРСТУХ)
   ПЕРЕД запросом к auto.ru и проверить, что поиск auto.ru находит номер,
   записанный клиентом латиницей (сейчас регэксп пропускает латиницу, но
   ищет ли auto.ru по латинской записи — проверить на их стороне).
3. **Код региона по списку:** 2-значные 01-99; 3-значные только с ведущей
   1/7/9. «К647МУ211» сейчас проходит регэксп и уходит в пустой поиск.
4. **Различимые статусы ошибки:** «нет кода региона» / «не похоже на номер» /
   «не найден в базе» — чтобы модель спрашивала конкретное («уточните регион,
   например 33»), а не дважды слепо «напишите ещё раз» (кейс А). Плюс
   промпт-поведение: после второй неудачи предлагать продолжение без оценки
   (осмотр в салоне), не бросать клиента до таймаута. Данные: в кейсе Б
   (sess_13123458_021811SE, логи в архиве) модель передала «К647МУ» без
   региона — инструктировать модель передавать регион, если клиент назвал
   его отдельным токеном («К647му 211» — «211» здесь пробег, но «К647му 33»
   — регион; различение — тоже довод в пользу явного вопроса о регионе).
