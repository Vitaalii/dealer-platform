# Тестовый контур v3.0: импорт, привязка, запуск, критерии приёмки

Прод-цепочка (AI Agent v2.0 и все его саб-воркфлоу) не перезаписывается и не
изменяется. Тестовый контур — параллельный набор воркфлоу на том же инстансе:
имена с префиксом `[TEST] `, webhook-пути с суффиксом `-test`. Файлы —
`flow/test-contour/` (генератор `nocodb/build_test_contour.py`; правки — только
через перегенерацию). Внутренние имена нод не меняются: они видны только внутри
своего воркфлоу и между воркфлоу не конфликтуют.

> ## ⚠️ Расхождение прод-файла с боевым n8n (с 2026-08-10, план 2026-08-10-001)
>
> **`flow/TOOL_ AUTO.RU EVALUATION.json` на диске содержит правку, которой нет в
> боевом воркфлоу**, и будет содержать её до отдельного согласования: нода
> `Code in JavaScript` отдаёт `found_info` + `plate` для личного кабинета (U1).
> Выкат в прод в скоуп плана не входит — проверка идёт на форке
> `[TEST] TOOL: AUTO.RU EVALUATION`.
>
> **Не импортировать `flow/TOOL_ AUTO.RU EVALUATION.json` в боевой n8n.**
> Импорт «свежего файла» увезёт непроверенную правку живьём: воркфлоу оценки
> зовут и прод-цепочка (AI Agent v2.0), и [TEST]-контур.
>
> Пометка снимается вместе с фактической синхронизацией прода — одновременно
> здесь, в стикере на канве воркфлоу и в шапке jsCode правленой ноды.

## B. NocoDB

Контур работает на новых таблицах базы TG_BOT_V1: `Intents`, `Prompt_Blocks`,
`Intent_Block_Map`, `Resolver_Shadow_Log` — они уже созданы и наполнены, к
прод-таблице Prompts контур не обращается. Каталожные чтения (Car Search)
идут в дилерские таблицы по `data_routing` из payload — только чтение.
Ничего настраивать не нужно.

«OpenRouter account» и «OpenRouter Account» (openAiApi, fallback gpt-4.1-mini)
по их реальным ID — при импорте в тот же инстанс подтянутся автоматически.

## D. Локальный бот (unifiedbot_dev_refactor)

В `.env` локального бота:

```
N8N_WEBHOOK_URL=https://<хост-n8n>/webhook/ai-handoff-v3-test
N8N_RESOLVER_SHADOW_URL=https://<хост-n8n>/webhook/ai-resolver-shadow-test   # опционально
```

Обратный канал (finalize): тестовый Save to CRM должен POST-ить
`/n8n_callback` на адрес, по которому доступен локальный бот (туннель
ngrok/cloudflared, если бот на локальной машине). Тестовые диалоги вести с
тестовым deal_id/дилером — finalize обновляет Bitrix через локального бота.
