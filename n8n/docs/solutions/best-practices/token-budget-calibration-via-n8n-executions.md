# Токен-бюджеты промптов калибровать фактическим замером из n8n executions, а не расчётом симв/токен

## Context

План 2026-07-17-001 задал R8 «вход резолвера ≤ ~1100 токенов», опираясь на расчётную калибровку origin-документа (~4.4 симв/токен, «текущий промпт ~550 ток.»). Параллельно `lint_check.py` жил на другой расчётной калибровке (2.5 симв/токен, `Tokens_est × 1.6`). Расхождение между двумя расчётами — 1.8 раза; сам план честно пометил, что порогом они не являются, и потребовал фактический замер до старта работ.

Замер показал: текущий промпт резолвера — уже **1017–1076 входных токенов при 13 интентах** (вдвое больше расчётной оценки), реальное отношение для русского текста — **3.17–3.33 симв/токен**. Требование ~1100 ток. было невыполнимо «по построению»: R8 пришлось поднять до ~2700 ток. в плане и origin ещё до правки кода.

## Guidance

Снимать фактический входной токен-каунт из n8n executions API — usage вендора лежит в данных исполнения LLM-под-ноды, отдельный ключ OpenRouter не нужен:

```python
# 1) успешные исполнения воркфлоу
GET {N8N_API_URL}/executions?workflowId=<id>&status=success&limit=10
# 2) полные данные одного исполнения
GET {N8N_API_URL}/executions/<exec_id>?includeData=true
# 3) в data.resultData.runData:
#    - нода 'Build Prompt' -> json.prompt        (фактический текст промпта, длина в символах)
#    - под-нода 'OpenRouter Flash Lite' -> рекурсивно найти dict с ключом promptTokens
# 4) симв/токен = len(prompt) / promptTokens; усреднить по ~10 исполнениям
```

Из замера выводить порог в символах: `char_budget = токен-бюджет × консервативное отношение` (минимум по выборке, здесь 3.17). Фикс-часть промпта (шаблон + история + сообщение без списка интентов) мерить исполнением реального jsCode с пустым списком, не оценкой.

Захардкоженные константы с источником в комментарии (замер 2026-07-17, exec 2449–2494):

- `nocodb/lint_check.py` / `build_lint_workflow.py`: `RESOLVER_PROMPT_CHAR_BUDGET = 8560` (2700 × 3.17), `RESOLVER_FIXED_CHARS = 2433`;
- `flow/lib/resolver_prompt_sim.test.mjs`: `PROMPT_CHAR_BUDGET = 8560` — тест собирает самую широкую комбинацию (combo, все интенты активны, история 8×150 симв.) и сверяет длину.

## Why This Matters

Расчётные калибровки симв/токен для русского текста расходятся с реальностью в 1.8–2 раза — пороги на их основе либо ложно тревожат, либо молчат, а требования планов оказываются невыполнимыми или бессмысленно мягкими. Одна из двух расчётных калибровок в этом репо занижала текущий промпт вдвое. Замер по 10 реальным вызовам занимает минуты и даёт стабильное отношение (разброс 3.17–3.33), на котором можно строить и требования, и линт, и тесты.

## When to Apply

- Перед фиксацией любого токен-бюджета в требованиях: сначала замер текущего состояния, потом число в документе.
- При настройке порогов в символах (линт, sim-тесты): выводить из токен-бюджета через консервативное замеренное отношение.
- После изменений, меняющих состав промпта: пересчитать и худший случай (worst-case комбинацию), и фикс-часть.
- **Бюджет считать по полному будущему состоянию строк, а не только по новым.** Вход резолвера собирается из строк `Intent_ID | Description | Примеры` ВСЕХ активных интентов сценария, поэтому PATCH-дописки к Description существующих интентов входят в бюджет наравне с новыми строками. Планируя правку таблицы интентов, worst-case считать по объединению: живые строки + патчи существующих + новые (инцидент 2026-07-22: проекция +2 интента давала combo 8454 из 8560, но после дописок к Description `request_phone`/`propose_visit` реальный worst-case подскочил до 8631 — за бюджет; починка — ужатие формулировок). Реализовано в `nocodb/add_needcheck_v303.py:budget_check()`.
- Если usage в n8n недоступен (нода без tokenUsage) — искать по всем нодам исполнения рекурсивно ключи `promptTokens`/`prompt_tokens`; статистика OpenRouter-дашборда — запасной вариант, требующий ручного доступа.

## Examples

Замер 2026-07-17 ([TEST] Tool: Resolver Core, 10 исполнений):

| exec | символов | promptTokens | симв/ток |
|---|---|---|---|
| 2494 | 3281 | 1017 | 3.23 |
| 2488 | 3346 | 1055 | 3.17 |
| 2464 | 3583 | 1076 | 3.33 |

Проекция после снятия стадийного фильтра (combo, 36 интентов, история 8×150): ~8120 симв. ≈ ~2500 ток. → R8 обновлён с ~1100 до ~2700 ток. в `docs/plans/2026-07-17-001-…-plan.md` и origin-документе **до** старта реализации — тест не «подгонялся» под желаемый порог.
