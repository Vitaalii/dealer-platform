# Пропуски данных чинить у источника, а не защитными правилами в промпте LLM

## Context

Бот в двух тестах (1) здоровался «Здравствуйте, Клиент!» при отсутствии имени и (2) писал «получил вашу заявку на покупку [Модель] [Комплектация] в кредит» с литеральными шаблонами, когда модель/комплектация не прилетели от Python.

Ключевое наблюдение при разборе: защитные правила в промпте **уже были** — блок `G-02_VOICE` содержал и «если имя равно "Клиент" → без имени», и «ЗАПРЕЩЕНО выводить имена технических переменных». Но модель проигнорировала оба правила в обоих тестах. То есть проблема была не в отсутствии правила, а в том, что на правило нельзя полагаться как на исполнительный механизм.

## Guidance

Разделяй два слоя и чини каждый в своём:

1. **Не вставляй значения-плейсхолдеры в контекст LLM.** Если у поля нет значения — отдавай модели пустоту, а не «осмысленный» дефолт. Питоновский дефолт `user_name = "Клиент"` (заглушка для UI/CRM) утекал в `user_data.name` payload'а и читался моделью как настоящее имя. Нормализуй на границе перед AI-payload: приводи «отравленные» дефолты к `""`, чтобы отсутствие данных было честным. Дефолты для других потребителей (CRM/Bitrix, где имя контакта обязано быть) при этом не трогай.

2. **Промпт должен обрабатывать отсутствие данных явно, а не только запрещать плохой вывод.** Прямой приказ «Сообщи, что получил заявку на покупку [Модель] [Комплектация]» перебивает далёкое общее правило «не выводи переменные». Добавь правило подстановки **в точке использования** (или преамбулом с объявленным приоритетом): «значения в `[...]` бери только из данных; если значения нет — не выводи шаблон и имя переменной, переформулируй фразу без него».

3. **Соблюдение промпт-правил моделью — вероятностное, не гарантированное.** Где можно — форсируй детерминированно у источника (нормализация payload). Где приходится полагаться на промпт — делай инструкцию локальной и приоритетной, а не одной строкой в общем блоке. Промпт-гард держи как defense-in-depth поверх источникового фикса, а не как единственную защиту.

## Why This Matters

Исполнение инструкций LLM недетерминированно: одно и то же правило то срабатывает, то нет. Значение-заглушка и безусловный плейсхолдер надёжно утекают в клиентский текст, и «усиление правила в промпте» этого не лечит — модель уже игнорировала правило. Источниковый фикс (нормализация имени) убирает симптом во всех сценариях сразу и детерминированно; промпт-правило остаётся страховкой. Диагностика «правило есть, но не исполняется» — сигнал чинить контракт данных, а не дописывать ещё одно правило.

## When to Apply

- Любая сборка AI-payload, где опциональные поля получают строковый дефолт вместо пустого значения
- Любой промпт, который велит модели назвать значение из контекста ([Модель], [Комплектация], [Сумма], имя)
- Симптом «в промпте есть правило, но модель его не соблюдает» — не усиливай правило, а проверь источник данных

## Examples

Источник — нормализация имени перед AI-payload (`main.py`):

```python
def clean_ai_name(name) -> str:
    # "Клиент" — UI/CRM-заглушка при отсутствии имени; для модели это
    # «отравленное» значение (здоровается «Здравствуйте, Клиент!»).
    if not name:
        return ""
    cleaned = str(name).strip()
    if cleaned.casefold() == "клиент":
        return ""
    return cleaned

# было:  "user_data": {"name": user_name}
# стало: "user_data": {"name": clean_ai_name(user_name)}
```

Промпт — обработка отсутствия данных преамбулом с приоритетом (greeting-блоки):

```
# было (безусловно):
Сообщи, что получил заявку на покупку [Модель] [Комплектация] в кредит.

# стало (преамбул в начале блока, приоритет над фразами ниже):
ЗНАЧЕНИЯ В КВАДРАТНЫХ СКОБКАХ ([Модель], [Комплектация], [Сумма] ...):
подставляй ТОЛЬКО из данных. Если значения нет — НЕ выводи сам шаблон в
скобках и имя переменной; переформулируй фразу без него (нет модели →
«получил вашу заявку на покупку автомобиля»).
```
