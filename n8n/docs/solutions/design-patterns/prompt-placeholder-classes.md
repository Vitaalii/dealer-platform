# Три класса плейсхолдеров промпта

## Context

В текстах блоков `Prompt_Blocks` квадратные скобки означают три совершенно
разные вещи, и по виду они неразличимы: `[dealer_address]`, `[Модель]` и
`[SPLIT]` выглядят одинаково, но обслуживаются тремя разными механизмами.
Путаница уже стоила двух инцидентов с утечкой скобок в текст клиенту, причём
с противоположными причинами.

## Guidance

| Класс | Плейсхолдеры | Кто подставляет | Где код |
|---|---|---|---|
| **A — подставляет код n8n** | `[dealer_name]`, `[dealer_address]`, `[dealer_hours]` | `Prompt Compiler`, функция `subst()` | `nocodb/build_v3_workflow.py:395`; легаси-путь v2 — `main.py:1022-1024`, `main.py:1094-1096` |
| **B — заполняет модель** | `[Модель]`, `[Комплектация]`, `[Сумма]`, `[Имя клиента]`, `[credit_price]`, `[base_price]`, `[tradein_price]`, `[down_payment]`, `[monthly_payment]`, `[term]` | никто в коде; модель берёт значения из `<DATA_FROM_DATABASE>` | контекст собирает `Data Selector` (`ai_clean_context`: `model`, `complectations[].name`, `complectations[].price.*`, `user_data.name`) |
| **C — контракт с ботом** | `[SPLIT]`, `[CABINET_LINK]` | Python-бот в тексте ответа | `main.py:602-603` — разбор `[SPLIT]` |

Разделение зафиксировано в коде и держится обязательными кейсами:

- `nocodb/build_v3_workflow.py:365-366` — комментарий, объявляющий границу:
  «Прочие шаблоны в скобках трогать нельзя: `[Модель]`/`[Сумма]`/`[Имя клиента]`
  и подобные заполняет сама модель из `<DATA_FROM_DATABASE>`, а `[SPLIT]` и
  `[CABINET_LINK]` — контракт с ботом»;
- `flow/lib/v3_pipeline_sim.test.mjs:1265` — кейс «дилер: класс B не тронут»;
  рядом кейс на класс C.

**Правила:**

1. **`subst()` расширять только осознанно.** Она подставляет ровно три токена
   класса A по точному совпадению. Добавление туда токена класса B сломает
   ожидание модели, класса C — контракт с ботом.
2. **Новый шаблон — сразу определить класс.** Если значение приходит в
   `ai_clean_context`, это класс B и кода не требуется. Если значения в контексте
   нет, класс B работать не будет: модель выведет скобки или выдумает значение.
3. **Пустое значение класса A ≠ пустая строка.** Рядом в `G-01_ROLE` стоит
   запрет выдумывать; пустая строка читается моделью как «данных нет, придумай».
   Поэтому в `DEALER_FALLBACK` лежит формулировка, которая сама диктует
   поведение, а не `""`.
4. **Класс B — вероятностный механизм.** Он работает, пока данные есть.
   Детерминированной гарантии нет и быть не может.

## Два инцидента, по одному на класс

**Класс A, «код не подставил».** Исполнение **3758**: клиент спросил адрес и
получил «находится по адресу: `[dealer_address]`. Мы работаем с
`[dealer_hours]`». В v2 подстановку делал бот, v3 собирает промпт сам, и
подстановки не было ни в одном узле. Лечение — коммит `0c37c47`, функция
`subst()` в `Prompt Compiler`.

**Класс B, «модель скопировала шаблон».** Бот писал «получил заявку на покупку
`[Модель] [Комплектация]` в кредит», когда данные не пришли от Python. Кода,
который должен был подставить, здесь нет по устройству — сбой в том, что блок
**безусловно приказывал** вывести фразу с шаблоном при отсутствующих данных.
Лечение — `nocodb/add_greeting_missingdata_v304.py`: преамбул «ПРАВИЛА
ПОДСТАНОВКИ» в начало пяти greeting-блоков плюс источниковая нормализация
`clean_ai_name()`.

## Замер работоспособности класса B (2026-09-16)

- Прод, исполнение **4395**: `"model": "НОВЫЙ HAVAL F7"` → «HAVAL F7 в
  комплектации Premium». Подстановка верная.
- Срез боевого трафика: 18 ходов с плейсхолдером класса B в промпте, дословных
  утечек **0**.
- Приёмка на `[TEST]`: 30 прогонов с заполненными данными — формат 30/30,
  утечек 0. Плюс 15 прогонов с **заведомо пустыми** `model` и комплектацией —
  дословных скобок 0 из 15: модель переформулирует фразу («уточните,
  пожалуйста, какую именно модель вы рассматриваете»).

Последнее — основание, по которому владелец отклонил добавление
преамбула-сторожа в `BLK_*_REFERENCE` (юнит U6 плана 2026-09-16-001).

## Why This Matters

Класс определяет, где чинить. Симптом у всех трёх одинаковый — клиент видит
скобки, — а причины и лечение противоположные: класс A чинится кодом, класс B —
данными на входе либо формулировкой блока, класс C — согласованием с ботом.
Неверно определённый класс ведёт к правке не того слоя: например, добавление
токена класса B в `subst()` выглядело бы как решение, а на деле сломало бы
остальные блоки, где тот же токен обязан дойти до модели.

## When to Apply

- Перед добавлением или правкой любого шаблона в квадратных скобках
- При разборе жалобы «в ответе клиенту оказались скобки»
- Перед правкой `subst()` в генераторе воркфлоу
