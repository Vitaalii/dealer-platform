# PDL-20 — разведка: доставка заявок (письмо, CallTouch, Метрика)

Задача: PDL-20 «[Работа] Разведка: доставка заявок — роботы Битрикса, API Метрики и CallTouch».
План — PDL-19 (разделы «Что сделаю» 1–6). Ответы владельца и скриншоты — в описании PDL-20.

## Что сделано

`docs/research/2026-10-16-lead-delivery-metrika-calltouch.md`:
- вывод коротко;
- как сейчас: по ответам владельца, четырём скриншотам и справочнику полей бота. Таблица того, что
  заменяет платформа;
- Метрика: OAuth и права, уровни доступа, проверка `my_grant`, создание целей, офлайн-конверсии
  (формат, окно 21 день, ~3 ч обработки, статусы, квоты), Measurement Protocol как запасной путь;
- CallTouch: метод `register` (токен не нужен), поля, ошибки, проверка токена журналом заявок,
  лимиты и баллы, три места возможного задвоения;
- Postbox: несколько адресатов, оплата по числу получателей, квоты, события по каждому адресу,
  стоп-лист;
- что нужно от сайта, что автоматизируется и что остаётся ручным, события для «Состояния доставки»;
- варианты с оценкой, рекомендация отдельно, 8 вопросов владельцу, список источников.

## Что не проверено

- Поведение API вживую: запросов не было по условиям задачи. Ответ `my_grant` при чужом счётчике,
  ответ CallTouch при неверном id сайта, работа загрузки — по документации.
- Метод загрузки офлайн-конверсий помечен Deprecated, замена в документации не названа.
  Перепроверить перед этапом 7.
- Что Метрика делает при повторной загрузке той же конверсии — не описано в документации.
- Лимит числа целей на счётчик, лимиты загрузок в сутки, размер суточного лимита баллов CallTouch.
- Статья CallTouch об автоматическом отслеживании форм не открывалась.
- Журнал Albato и роботы Битрикса — только по скриншотам. Повторная отправка при «памяти связки —
  при каждом изменении» — допущение.
- Песочница Postbox для новых аккаунтов не найдена.
