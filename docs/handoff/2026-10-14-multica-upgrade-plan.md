# Handoff: план обновления Multica v0.4.32 → v0.6.2 (2026-10-14)

- План: `docs/plans/2026-10-14-001-chore-multica-upgrade-v0.6.2-plan.md`. Этапы A (Ubuntu + перезагрузка),
  B (Multica), C (откат), D (проверки); риски, оценка простоя, совместимость с пилотом.
- Целевая версия v0.6.2: GitHub API `releases/latest`; образы backend и web под amd64 есть в GHCR.
- Главный вывод: промежуточная остановка не нужна. Раннер миграций применяет недостающие по имени,
  469 пропускается, бэкфилл для self-host выполняется миграцией 491. Подтверждено кодом
  `server/cmd/migrate/main.go` и upstream-тестом `skipped_469`.

- Ревью документа: coherence, feasibility, security-lens, adversarial. Правки внесены, включая
  фильтр логов перед отправкой: коды входа пишутся в лог, потому что почта не настроена.
- Решения владельца В1–В6 внесены в план (§6): v0.6.2, Caddy обновлять, устаревшие переменные
  оставить, дамп на Mac обязателен, репетиция B0 обязательна.
- Добавлен этап B0: репетиция на базе `multica_rehearsal` (свежий дамп, восстановление,
  `./migrate up` с `DO_NOT_TRACK=1`, ручное подтверждение имени базы, `dropdb`, контроль 429).
- На сервере выполнялись только команды на чтение (по разрешению владельца на эту задачу).
  При диагностике выведены значения трёх несекретных флагов (`ALLOW_SIGNUP`,
  `MULTICA_IMAGE_TAG`, `DISABLE_WORKSPACE_CREATION`); секреты не читались.
- Проверка секретов: gitleaks 8.30.1, официальный бинарник darwin_arm64, SHA-256 сверен с
  `gitleaks_8.30.1_checksums.txt`; утечек нет; бинарник удалён после проверки.
