ответы владельца на 6 вопросов плана и решение по Envybox — в описании PDL-18.

  - 7 вопросов владельцу.

## Что проверено и как

- Чтение снимков `bot/` и `n8n/` (`grep -n`, `sed -n`, разбор JSON воркфлоу скриптом только на чтение
  `python3 -I`). Часть разбора делали вспомогательные агенты; их ключевые утверждения я перепроверил сам по
  строкам, номера строк в отчёте сверены и поправлены.
- Счётчики для сверки: `grep -c` по `BitrixService`, `BITRIX_`, `UF_CRM`, `deal_id`; `grep -ci bitrix` по
  `n8n/flow/*.json` = 0; `grep -rn -i tiledesk bot/*.py bot/tests/*.py` — импортов нет.
- Правки [TEST]: сравнил узел `finalize_deal` боевого и [TEST] агента v3 и `client_mode` в резолвере — в снимке
  совпадают, то есть кода правок `effa014`/`f2de42d` в снимке нет.

## Что не проверено

- Тесты и скрипты не запускал (границы задачи и ответ 6 на план).
- Коды UF для полей из окружения (`BITRIX_FIELD_*`) — из справочника `bot/scripts/build_bitrix_fields_doc.py`,
  который собран по `.env` дева; значения боя не проверены. Поле ника контакта сопоставлено по смыслу.
- Кто переводит сделку в «Отправлено» — в коде бота не видно (это PDL-20).
- Содержимое правок `effa014`/`f2de42d` — только описание из плана `n8n/docs/plans/2026-10-09-003-…`.
- Оценки «мало / средне / много» — суждение автора.
- gitleaks: в этой среде не ставил (границы задачи запрещают установку). Секретов и персональных данных в
  документах нет — проверено чтением. Адреса старых серверов в отчёте приведены так же, как они записаны в файлах
  снимка, с указанием строки.
- Сторожевой хук заблокировал одну мою команду правки текста: в ней был адрес старой системы. Обходить его я не
  стал, поэтому адреса в отчёте остались.
