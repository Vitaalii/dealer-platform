- Единственное внешнее действие — `actions/checkout`, закреплено по SHA `3d3c42e5…` (метка v7.0.1, `gh api repos/actions/checkout/git/ref/tags/v7.0.1`).

- `infra/README.md`: разделы 14–18 (GHCR, автообновление, выпуск на бой, откат, ключи и запасной путь); правки владельца по шагам 2–5 и 7

## Отличия от плана PDL-35 (и почему)

- Номера разделов README — 14–18, а не 13–16: раздел 13 уже занят бэкапами (5.3, PR #32).
- `infra/backup/restore-check.sh` и README 13.4: имя образа базы теперь берётся из `IMAGE_PREFIX`/`PLATFORM_TAG` — иначе после перехода на GHCR
  пробное восстановление искало бы несуществующий `dealers/postgres:17`. В списке файлов плана этого не было, но без правки ломается 5.3.
- NocoDB не закреплён (остался `${NOCODB_VERSION:-latest}`): тег образа на Docker Hub подтвердить не удалось — обращение к hub.docker.com
  запрещено модом guard, а у NocoDB на GitHub нет сведений о тегах образа. Риск ниже, чем в плане: скрипты выкатки скачивают только три своих
  образа, `up -d` чужие образы повторно не скачивает (уже скачанный `latest` не меняется). n8n уже был закреплён `2.43.0`.
- `NOCODB_VERSION`, `N8N_VERSION`, `CADDY_VERSION` не добавлены в `.env.example`: так и было (у `NOCODB_VERSION`/`N8N_VERSION` уже были значения
  по умолчанию), а пустые строки сломали бы проверку `grep -c '=$' .env` → `0` в шаге 9. `PLATFORM_TAG` пишет скрипт сам.
- Без кэша сборки и без `docker/*` действий: обычные `docker build`/`docker push`. Меньше сторонних действий, которые надо закреплять;
  поддержку кэша реестра GHCR я не проверил.
- `release.yml` срабатывает и на `push` метки, и на `release: published` — не проверено, порождает ли создание метки через форму релиза
  событие `push`; повторный запуск безвреден (ставит ту же метку).

## Блокер: отправка `.github/workflows/`

`git push` отклонён GitHub: «refusing to allow a Personal Access Token to create or update workflow
.github/workflows/build.yml without workflow scope». Токен агента (аккаунт `astronautagent`, `gh auth status`) без права
`workflow`; менять токен и настройки исполнителю нельзя. Поэтому в ветку отправлен коммит без `.github/`, а коммит с тремя
workflow лежит локально в checkout задачи (ветка `agent/agent/c80226b28d4f`). PR не открыт: без workflow выкатка не работает,
а `infra/tests/test_workflows.py` без них падает. Решение — за владельцем (вопрос в задаче PDL-29).
