# PDL-31 — Этап 5.4: почта через Postbox

Задача: PDL-31, план — PDL-33 (комментарий «ИТОГ PDL-33»), одобрен Координатором 17.10 после ответов владельца
«1А 2А 3А 4А». Ветка `agent/agent/788ec3733d5e` от `main` (PR #31 и #32 уже слиты), PR в `main`.

## Что сделано

- `core/platform_core/config.py`: настройки почты `MailSettings` и `load_mail_settings`. Обязательные
  `MAIL_PROVIDER` (`postbox`/`log`) и `MAIL_FROM`. При `postbox` обязательны ещё `POSTBOX_KEY_ID` и
  `POSTBOX_SECRET_KEY`. Необязательные: `MAIL_FROM_NAME`, `MAIL_MAX_PER_SECOND` (1), `POSTBOX_ENDPOINT`,
  `POSTBOX_REGION` (`ru-central1`). `log` при `PLATFORM_ENV=prod` даёт `CONFIG ERROR`. Секрет хранится с `repr=False`.
- `core/platform_core/mail/`:
  - `__init__.py` — интерфейс `Mailer.send(to, subject, text, html=None) -> SendResult(message_id, recipients)`,
    ошибки `MailPermanentError` / `MailTemporaryError`, `normalize_recipients` (пробелы, регистр, дубли,
    вид `x@y.z`, 1–200 получателей), `build_mailer(settings)`;
  - `postbox.py` — `POST /v2/email/outbound-emails`, все адреса в `ToAddresses` одним письмом, имя отправителя
    кириллицей кодируется по RFC 2047 (`email.utils.formataddr`). Повторы при 429, 5xx, сбое сети и тайм-ауте 10 с:
    3 попытки, паузы 1 и 2 с плюс случайный сдвиг до 0,5 с. Остальные ответы — `MailPermanentError` с HTTP-кодом
    и `Code`. Поле `message` ответа не берётся (в нём бывают адреса). Между запросами процесса пауза не меньше
    `1 / MAIL_MAX_PER_SECOND`. HTTP идёт через `aiohttp`, он уже закреплён в `core/requirements.txt`;
  - `sigv4.py` — подпись AWS SigV4 на `hmac`/`hashlib`, сервис `ses`;
  - `log_mailer.py` — заглушка: в лог пишет только тему и число получателей;
  - `__main__.py` — `python -m platform_core.mail --to … [--to …]` → `SENT message_id=… recipients=N` или
    `MAIL ERROR: …`, код 1.
- `core/platform_core/app.py`: отправитель в `app[MAILER_KEY]` закрывается при остановке; при старте пишется строка
  `mail provider=<…>`.
- `infra/compose.yaml`: 8 переменных почты у сервиса `platform`. `infra/.env.example`: те же имена без значений.
  `infra/README.md`: шаг 9 дополнен строками почты, новый раздел 14 (консоль Postbox, DNS, `.env`, проверка
  по одной команде, «если что-то не так»). `core/README.md`: раздел о почте.
- Тесты: `core/tests/test_mail_config.py`, `test_mail_sigv4.py`, `test_mail_postbox.py`. В `test_config.py`
  в `full_env` добавлены две обязательные переменные почты.

## Отличия от плана

- `POSTBOX_KEY_ID` и `POSTBOX_SECRET_KEY` в `compose.yaml` обязательные (`:?`), хотя ядро требует их только при
  `postbox`. Так требует уже существующий тест `infra/tests/test_compose.py::test_no_literal_secrets`:
  все `*KEY*`/`*SECRET*` в compose — только через `:?`. Ослаблять проверку я не стал. Из-за этого
  **следующий `docker compose up` на тесте не пройдёт без ключа Postbox**, даже с `MAIL_PROVIDER=log`.
- В плане сказано «3 попытки с паузами 1 → 2 → 4 с». При 3 попытках пауз только две: 1 и 2 с.
  Пауза 4 с была бы перед четвёртой попыткой. Число попыток — `MAX_ATTEMPTS` в `postbox.py`.
- Код ответа Postbox при успехе — 200 (страница SendEmail, раздел «Ответ»). Код принимает любой 2xx.
- Эталон для теста подписи: набор тестов AWS `aws-c-auth`,
  `tests/aws-signing-test-suite/v4/post-x-www-form-urlencoded` (https://github.com/awslabs/aws-c-auth).
  Использованы учебные ключи AWS, ожидаемая подпись — `d3875051…0e0b`.

## Не проверено

- Реальная отправка через Postbox, DNS и `dkim=pass`: это делает владелец по `infra/README.md`, раздел 14.
- Принимает ли Postbox HTTP/1.1. На странице SendEmail указан HTTP/2, aiohttp работает по HTTP/1.1. Проверится
  шагом «Письмо одному адресу». Если не примет — нужен клиент с HTTP/2, а это новая зависимость и вопрос владельцу.
- `AiohttpTransport` и `build_app` локально не запускались: нет `asyncpg`, а запуск сетевых сервисов не нужен по
  задаче. Обе части проверятся на сервере (логи `mail provider=postbox`, команда `python -m platform_core.mail`).
- gitleaks не установлен. Учебные ключи AWS в `core/tests/test_mail_sigv4.py` могут дать ложное срабатывание.
- Запись SPF `include:spf.postbox.yandexcloud.net`: в официальной документации Postbox её нет, в README она
  помечена «только если предлагает консоль».
- Есть ли `dig` на vm.mini.

## Открытые вопросы

- Ключи Postbox обязательны в compose (см. «Отличия от плана»). Если тест нужно выкатывать раньше, чем появится
  Postbox, нужно решение владельца: разрешить `:-` для `POSTBOX_*` и поправить `test_no_literal_secrets`.
