# Решения владельца по платформе

Журнал решений владельца по продукту и архитектуре — основа для документа архитектуры (этап 4,
`docs/REQUIREMENTS.md`, «Этапы»). Ведёт Координатор со слов владельца, через PR; источник каждого
решения — разговор с владельцем (дата) и исследование, на которое оно опирается.
Решения о порядке работы агентов — в `COORDINATOR.md`, не здесь.

Обозначения: **решено** — владелец сказал явно; **рекомендация** — предложение исследования или
Координатора, владелец не решал; **открыто** — нужен ответ.

## Хранилище

Исследование: `docs/research/2026-10-16-storage.md` (PDL-13 план, PDL-14 работа).

| Вопрос | Статус | Решение / рекомендация | Дата |
|---|---|---|---|
| Схема хранилища | решено | Вариант Б: PostgreSQL новой платформы — источник истины; NocoDB подключена к ней как интерфейс для просмотра и ручных правок; админка платформы минимальная. Деньги и заявки в NocoDB — только чтение | 16.10 |
| Кто правит каталоги | решено (факт) | Грабер — данные из прайсов; владелец вручную — видимость (`Active`/`Active_N`) и фото | 16.10 |
| Где работает грабер после переезда | решено | Остаётся на старом сервере; дорабатывает отдельный CE | 16.10 |
| Фото каталога | решено | Файлы — в S3 Yandex Cloud, в базе только ссылки | 16.10 |
| Цвета, склад, программы, ставки | решено (факт) | Сейчас заполняют отдельные скрипты; в ближайшее время всё это будет делать грабер | 16.10 |
| Лицензия NocoDB (Sustainable Use License, внутреннее использование) | решено | Устраивает: NocoDB использует только владелец, бесплатно | 16.10 |
| Как бот и n8n читают каталог | решено | Из PostgreSQL напрямую, NocoDB не на критическом пути (урок падения NocoDB 06.10) | 16.10 |
| Кто выгружает разовую копию каталогов из боевой NocoDB | решено | CE старой системы, бережным чтением; агентам платформы подключаться нельзя | 16.10 |
| Общая колонка `Active` рядом с настройками дилера | решено | Оставить ради совместимости с грабером (он её читает) | 16.10 |
| Проверка «грабер + NocoDB поверх внешней PostgreSQL» | решено | Включить в план этапа 5 (тестовый стенд); запасной вариант — таблицы грабера во внутренней базе NocoDB | 16.10 |

## Почта

Исследование: `docs/research/2026-10-16-mail-and-backups.md` (PDL-15 план, PDL-16 работа).

| Вопрос | Статус | Решение / рекомендация | Дата |
|---|---|---|---|
| Объём писем | факт | 30–200 заявок в месяц на дилера, 2–8 адресов на дилера, ~50 дилеров через полгода → ~3 000–95 000 писем в месяц | 16.10 |
| Входящая почта / ящик поддержки | решено | Не нужна. Поддержка дилеров — отдельным ботом | 16.10 |
| Свой почтовый сервер | факт | Не подходит: у Hostkey закрыты исходящие порты 25/465/587/2525; отправка — через сервис по HTTP API | 16.10 |
| Сервис отправки | решено | Старт на Yandex Cloud Postbox (рубли, РФ, оплата за письмо — на малом объёме сотни рублей в месяц). Код отправки — со сменяемым сервисом (API Postbox совместим с AWS SES); при росте объёма сравнить с Unisender Go / Resend. Свой сервер, open source (нужен порт 25) и SMTP Gmail не подходят — порты Hostkey закрыты | 16.10 |
| Поддомен отправки | решено | `notify.<домен>` | 16.10 |
| Счета и акты | решено | Только в кабинете; письмом — уведомление со ссылкой, без вложения | 16.10 |

## Доставка заявок

Исследование: PDL-19 план, PDL-20 работа (в процессе). Сейчас — со слов владельца 16.10.

| Вопрос | Статус | Решение / рекомендация | Дата |
|---|---|---|---|
| Как сейчас | факт | Письмо, CallTouch и Метрика срабатывают на стадии сделки «Отправлено». Письмо — робот Битрикса; CallTouch — через Albato; Метрика — приложение из маркетплейса Битрикс24. Под дилера вручную настраиваются адреса писем и конверсия в Метрику | 16.10 |
| Главная проблема писем сейчас | факт | Нельзя отправить одно письмо нескольким адресатам | 16.10 |
| CallTouch | решено | Прямая отправка заявок в API CallTouch; от дилера — id сайта в CallTouch и токен (берёт в своём кабинете) | 16.10 |
| Метрика | решено | При регистрации запрашивать у дилера доступ к счётчику с правом редактирования; через OAuth платформы передавать события (заявки, в том числе из бота) в его Метрику | 16.10 |
| Envybox (виджет обратного звонка) | решено | Не нужен, убираем | 16.10 |
