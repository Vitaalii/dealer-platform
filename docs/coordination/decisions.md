# Решения владельца по платформе

Журнал решений владельца по продукту и архитектуре — основа для документа архитектуры (этап 4,
`docs/REQUIREMENTS.md`, «Этапы»). Ведёт Координатор со слов владельца, через PR; источник каждого
решения — разговор с владельцем (дата) и исследование, на которое оно опирается.
Решения о порядке работы агентов — в `COORDINATOR.md`, не здесь.

Обозначения: **решено** — владелец сказал явно; **рекомендация** — предложение исследования или
Координатора, владелец не решал; **открыто** — нужен ответ.

Свой сервер, open source (нужен порт 25) и SMTP Gmail не подходят — порты Hostkey закрыты | 16.10 |

## Доставка заявок

Исследование: PDL-19 план, PDL-20 работа (в процессе). Сейчас — со слов владельца 16.10.

| Вопрос | Статус | Решение / рекомендация | Дата |
|---|---|---|---|
| Как сейчас | факт | Письмо, CallTouch и Метрика срабатывают на стадии сделки «Отправлено». Письмо — робот Битрикса; CallTouch — через Albato; Метрика — приложение из маркетплейса Битрикс24. Под дилера вручную настраиваются адреса писем и конверсия в Метрику | 16.10 |
| Главная проблема писем сейчас | факт | Нельзя отправить одно письмо нескольким адресатам | 16.10 |
| CallTouch | решено | Прямая отправка заявок в API CallTouch; от дилера — id сайта в CallTouch и токен (берёт в своём кабинете) | 16.10 |
| Метрика | решено | При регистрации запрашивать у дилера доступ к счётчику с правом редактирования; через OAuth платформы передавать события (заявки, в том числе из бота) в его Метрику | 16.10 |
| Envybox (виджет обратного звонка) | решено | Не нужен, убираем | 16.10 |
| Заявки «По телефону» | решено | Передавать в CallTouch и Метрику, как и остальные; письмо — тем же порядком, что заявки из чата, с другим текстом | 16.10 |
| Идентификатор для офлайн-конверсии | решено | Передавать Яндекс ClientID посетителя (сейчас приходит из формы Tilda в поле сделки `Ya_id`), при наличии — yclid; поля «Идентификаторы посетителя» и «Сумма» в нынешнем роботе — заглушки | 16.10 |
| Значение «В мессенджере» в «Тип лида 1» | факт | Приходит из заявки с формы Tilda | 16.10 |
| Цена конверсии | решено | На старте не передавать | 16.10 |
| Источник офлайн-конверсий | решено | Только платформа; при подключении дилер отключает передачу заявок из CallTouch в Метрику (против задвоения) | 16.10 |
| Автоотслеживание форм CallTouch на сайтах платформы | решено | Выключить: заявки в CallTouch отправляет платформа | 16.10 |
| Логин платформы в Метрике | решено | Отдельный служебный аккаунт Яндекса компании с двухфакторной защитой | 16.10 |
| Адресаты письма о заявке | решено | Все адреса дилера в «Кому» одним письмом | 16.10 |
| Заявки из мессенджера без визита на сайт | решено | В Метрику не попадают — принять | 16.10 |

## Масштаб и сервер

| Вопрос | Статус | Решение / рекомендация | Дата |
|---|---|---|---|
| Бюджет на серверы | решено | Ориентир ~3 000 ₽ в месяц — как сейчас за контейнеры старой системы | 16.10 |
| Целевой масштаб | решено (факт) | Около 100 сайтов дилеров; сейчас в старой системе работают 2 тестовых сайта, поэтому нынешнее потребление — только нижняя граница | 16.10 |
| Площадка | решено | Только российские площадки Hostkey | 16.10 |
| Серверы | решено | Рекомендуемый вариант 2 830 ₽/мес: бой — Hostkey vm.medium (6 ядер, 12 ГБ, 160 ГБ SSD), тест — vm.v2-nano (4 ГБ), Uptime Kuma — vm.pico (`docs/research/2026-10-16-server-sizing.md`). Перед заказом (этап 5) уточнить у поддержки Hostkey: автобэкап на medium, скидки, НДС, переход на больший тариф без смены IP | 16.10 |
| NocoDB на тестовом сервере | решено | Только на время проверки грабера; надолго — тариф vm.mini (+280 ₽) | 16.10 |
| DNS сайтов дилеров | решено | Дилеры указывают CNAME на имя платформы (переезд сервера без правок у дилеров) | 16.10 |
| Допущение нагрузки | решено (факт) | ~3 диалога на одну заявку, ~10 реплик в диалоге — похоже на правду | 16.10 |
| Производственный календарь | решено | Только федеральный, без региональных праздников | 16.10 |
| Источник календаря | решено | Kuzyak Calendar API — основной, isDayOff — сверка, своя копия на текущий и следующий год; BasicData не подходит (`docs/research/2026-10-16-production-calendar.md`) | 16.10 |
| Отсчёт срока апелляции | решено | День доставки не считается; срок истекает в конце 3-го рабочего дня по московскому времени | 16.10 |
| Ручной ввод переносов | решено | Если сервисы не обновились — владелец через админку, раз в год, по напоминанию платформы | 16.10 |
