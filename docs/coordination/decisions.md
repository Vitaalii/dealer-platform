# Решения владельца по платформе

Журнал решений владельца по продукту и архитектуре — основа для документа архитектуры (этап 4,
`docs/REQUIREMENTS.md`, «Этапы»). Ведёт Координатор со слов владельца, через PR; источник каждого
решения — разговор с владельцем (дата) и исследование, на которое оно опирается.
Решения о порядке работы агентов — в `COORDINATOR.md`, не здесь.

Обозначения: **решено** — владелец сказал явно; **рекомендация** — предложение исследования или
Координатора, владелец не решал; **открыто** — нужен ответ.

## Хранилище

Исследование: `docs/research/2026-10-16-storage.md` (PDL-13 план, PDL-14 работа).

| Вопрос | Статус | Решение / рекомендация | Дата |
|---|---|---|---|
| Схема хранилища | решено | Вариант Б: PostgreSQL новой платформы — источник истины; NocoDB подключена к ней как интерфейс для просмотра и ручных правок; админка платформы минимальная. Деньги и заявки в NocoDB — только чтение | 16.10 |
| Кто правит каталоги | решено (факт) | Грабер — данные из прайсов; владелец вручную — видимость (`Active`/`Active_N`) и фото | 16.10 |
| Где работает грабер после переезда | решено | Остаётся на старом сервере; дорабатывает отдельный CE | 16.10 |
| Фото каталога | решено | Файлы — в S3 Yandex Cloud, в базе только ссылки | 16.10 |
| Цвета, склад, программы, ставки | решено (факт) | Сейчас заполняют отдельные скрипты; в ближайшее время всё это будет делать грабер | 16.10 |
| Лицензия NocoDB (Sustainable Use License, внутреннее использование) | решено | Устраивает: NocoDB использует только владелец, бесплатно | 16.10 |

| Кто выгружает разовую копию каталогов из боевой NocoDB | рекомендация | CE старой системы, бережным чтением; агентам платформы подключаться нельзя | — |
| Общая колонка `Active` рядом с настройками дилера | рекомендация | Оставить ради совместимости с грабером (он её читает) | — |
| Проверка «грабер + NocoDB поверх внешней PostgreSQL» | рекомендация | Включить в план этапа 5 (тестовый стенд); запасной вариант — таблицы грабера во внутренней базе NocoDB | — |
