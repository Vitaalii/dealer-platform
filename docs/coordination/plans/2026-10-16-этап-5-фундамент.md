# План этапа 5 — фундамент на VPS

Версия 1.1, 2026-10-17 (одобрен владельцем 17.10; уточнено: тест — vm.mini на `dealers.autodc.org`, бой — позже, мониторинг — UptimeRobot). По регламенту автономии (`docs/coordination/AUTONOMY.md`). Вступает в силу после слов
владельца «план этапа 5 одобряю». Основание — `docs/architecture/ARCHITECTURE.md` (одобрен 16.10), разделы 2, 7,
8, 9 и `docs/coordination/decisions.md`.

## Цель

Работающие боевой и тестовый серверы с каркасом всей платформы, выкаткой из GitHub, бэкапами, мониторингом и
почтой; каталог марок в новой базе; проверка «грабер + NocoDB поверх PostgreSQL». После этапа 5 этапы 6 и 7
пишут код поверх готового фундамента, а слияние в `main` перестаёт быть выкаткой на бой (фаза B регламента).

## Критерии готовности

1. Тест и бой подняты одним `docker compose` из `infra/` (лимиты памяти — `ARCHITECTURE.md` 7.3): Caddy с
   сертификатами, PostgreSQL со схемами `catalog`, `content`, `platform_ro` и ролями (2.2), NocoDB поверх
   PostgreSQL с правами по схемам, n8n (отдельная база, настройки 7.3), каркас сервиса платформы на Python
   (проверка здоровья, проверка ключей при старте — 7.4), контейнер бота-заглушки (сам перенос бота — этап 7).
2. Выкатка: GitHub Actions собирает образы без секретов; тест обновляется из `main` сам; бой — по метке
   релиза с подтверждением владельца (В12). Описан откат на предыдущую версию.
3. Бэкапы: pgBackRest — непрерывный архив в Yandex Object Storage, ежедневный дамп, еженедельное
   автоматическое пробное восстановление; сигналы в Healthchecks.io; UptimeRobot (аккаунт владельца) проверяет
   сайты. Одно пробное восстановление сделано вручную и записано.
4. Почта: модуль отправки через Postbox со сменяемым сервисом; домен подтверждён, SPF, DKIM, DMARC `p=none`;
   тестовое письмо одному получателю и одно письмо нескольким дошли (7.6).
5. Каталог: схема каталога марок и загрузка разовой копии на тесте (2.4; копию выгружает CE старой системы).
6. Стенд «грабер + NocoDB поверх PostgreSQL» на тесте проверен; результат записан; если не прошёл —
   включён запасной вариант (таблицы грабера во внутренней базе NocoDB) — `decisions.md`, «Хранилище».
7. Для владельца — `infra/README.md`: первичная настройка сервера командами по одной, выкатка, откат,
   восстановление из бэкапа, где лежат ключи (без значений).

## Что остаётся за владельцем (стоп-лист — собрано заранее)

Сразу после одобрения плана, параллельно с 5.1:

1. **Домен:** какой домен и поддомены у платформы — для теста, боя, `notify.` (почта), имени для CNAME дилеров.
   *Это решение — нужен ответ.*
2. ~~Тестовый сервер~~ — заказан 17.10 (vm.mini). Боевой vm.medium — ближе к первой выкатке на бой; перед
   заказом — вопросы поддержке (НДС, скидка, автобэкап на medium, переход medium → v2-medium без смены IP).
3. Зарегистрировать Yandex Cloud: Postbox (подтвердить домен, поднять квоты), Object Storage (бакеты для копий
   базы и фото).
4. Healthchecks.io (если UptimeRobot не умеет сигналы заданий); Telegram-бот для оповещений — есть.
5. GitHub: если понадобится — ключи для выкатки в секреты репозитория (план 5.2 скажет, какие).

По ходу этапа:

6. Команды первичной настройки на серверах — по `infra/README.md`, по одной.
7. Положить ключи в окружение серверов.
8. DNS-записи (сервера, почта) у регистратора домена.
9. Попросить CE старой системы: выгрузку каталогов (бережное чтение) и перенастройку грабера на тестовую NocoDB
   для стенда 5.6 (В7: доступ только с IP старого сервера плюс токен).
10. Одобрить первую выкатку на бой.

Ориентир времени владельца: ~3–4 часа на весь этап, в основном регистрации и команды на серверах

## Риски

- Объём ручной работы владельца на серверах — снижается README с командами по одной и проверкой после каждой.
- GitHub Actions и реестр образов для приватного репозитория — лимиты бесплатного тарифа не проверены; план 5.2
  проверит по документации и при необходимости вынесет выбор владельцу.
- Грабер не примет NocoDB поверх PostgreSQL — запасной вариант уже решён.
- Квоты Postbox на старте (200 писем в сутки) — поднять заранее (владелец).
- Метод загрузки офлайн-конверсий Метрики устарел — не этот этап, проверить в плане этапа 7.
