# Доступ координатора (чат claude.ai) к доске Multica

Задача: PDL-6, план — PDL-5 (версия 2 и правки в комментариях). Дата исследования: 2026-10-15.
Источники читались в этот день; страницы поддержки Anthropic даты правки не показывают.

## Вывод коротко

1. **Вариант Б (свой MCP-коннектор) технически возможен на тарифе Max**, в том числе в чате
   внутри проекта — прямого запрета для Max в документации нет, но и прямого подтверждения тоже
   (см. Б.1). Проверяется за минуту в интерфейсе.
2. **Слабое место — авторизация.** claude.ai принимает либо OAuth, либо «без входа». Статичный
   токен в заголовке — бета «для ограниченного набора организаций»; есть ли она у личного Max —
   не подтверждено. Готовый MCP-сервер, который подходит лучше всего, умеет только статичный
   токен. Значит, нужно либо проверить, видна ли у вас секция **Request headers**, либо
   жить без входа (фильтр по IP Anthropic + секретный адрес), либо дописывать OAuth.
3. **В Multica v0.6.2 нет токенов и ролей «только чтение».** Личный токен (`mul_`) работает
   от имени пользователя во всех его пространствах; у роли `member` есть право создавать,
   менять и удалять задачи. «Только чтение» придётся собирать из слоёв: отдельный пользователь
   Multica + MCP-сервер в режиме только чтения + фильтр методов в Caddy.
4. **Официального MCP-сервера у Multica нет.** Из сторонних самый подходящий —
   `strider2038/multica-mcp` v0.2.0: Go, ~2300 строк, MIT, сеть (Streamable HTTP), в режиме
   только чтения не регистрирует инструменты записи. Зрелость низкая (4 звезды, один автор).
5. **Объём работ** — примерно 1–2 рабочих дня агента на подготовку (ревью кода, compose, Caddy,
   инструкция) и около часа действий владельца. Если нужен свой OAuth — плюс 2–4 дня
   (оценка, не проверена).

Рекомендация — в конце документа, отдельно от фактов.

### Б.2. Multica v0.6.2: API, токены, роли

**API.** Всё нужное для чтения есть в обычном REST API [M]:

- `GET /api/issues` — список задач, фильтры по статусу, проекту, исполнителю, `limit` до 100
  и `offset` (`server/internal/handler/issue.go:1438-1450`);
- `GET /api/issues/{id}` и `GET /api/issues/{id}/comments` (`server/cmd/server/router.go:2026,2032`);
- `GET /api/projects`, `GET /api/agents` (`router.go:2131,2242`).

Авторизация — `Authorization: Bearer <токен>`, пространство — заголовок `X-Workspace-ID` или
`X-Workspace-Slug` (`server/internal/middleware/auth.go:299-311`,
`server/internal/middleware/workspace.go:109-145`).

**Токены.** Права «только чтение» нет:

- личный токен `mul_` — в таблице только `user_id`, имя, хэш, срок, отзыв; полей прав
  и пространства нет (`server/migrations/011_personal_access_tokens.up.sql`);
- документация Multica: «It can access every workspace and API you have access to»
  (`apps/docs/content/docs/auth-tokens.mdx:20`);
- срок — 30, 90 дней, год или бессрочно (`auth-tokens.mdx:22`);
- токены с правами (`issues:read`, `comments:read` и т. п.) есть только у плагинов, и ими
  нельзя получить список задач: публичный `/v1` умеет только одну задачу и её комментарии
  (`server/pkg/publicapi/v1/routes.go:11-19`, `server/pkg/plugincontract/manifest.go:91-105`).

**Роли.** Только `owner`, `admin`, `member` (`server/migrations/001_init.up.sql:30`). Роли
«наблюдатель» нет. Документация: «creating issues, writing comments — is open to all members»
(`apps/docs/content/docs/members-roles.mdx:8`). Например, удаление задачи доступно любому
участнику (`router.go:2029`). Ограничить участника одним проектом нельзя: таблицы доступа
к проектам в миграциях нет.

**Персональные данные в ответах.** Задачи и комментарии содержат только ID авторов и
исполнителей, без почты (`server/internal/handler/issue.go:38-97`,
`server/internal/handler/comment.go:29-68`). Почта есть в списке участников
`GET /api/workspaces/{id}/members` (`server/internal/handler/workspace.go:502-510`) и в истории
запусков `GET /api/issues/{id}/task-runs`. Текст задач и комментариев может содержать что угодно.

**Официального MCP-сервера нет.** MCP в коде Multica — только на стороне агентов. Запросы на
официальный сервер открыты без ответа разработчиков:
https://github.com/multica-ai/multica/issues/5125, https://github.com/multica-ai/multica/issues/1351.

- подсказок `readOnlyHint` у инструментов нет (`internal/mcp/server.go:482-497`);

- размер — ~2300 строк Go без тестов, одна внешняя зависимость — официальный
  `modelcontextprotocol/go-sdk v1.6.0` (`go.mod:5`). Код можно прочитать целиком за пару часов.

### Б.4. Как сделать «только чтение»

| Слой | Что даёт | Чего не закрывает | Надёжность |
|---|---|---|---|
| Права токена Multica | — | Таких прав нет (Б.2) | Нет |
| Отдельный пользователь Multica, роль `member`, только в нужном пространстве | Утечка токена не даёт доступ к пространствам владельца и к настройкам | `member` может создавать, менять, удалять задачи и писать комментарии; комментарий с упоминанием агента запускает платный запуск | Средняя |
| MCP-сервер в режиме только чтения | Координатор физически не видит инструментов записи | Если взломан сам контейнер или утёк токен — запись возможна в обход MCP | Средняя (код не проверен аудитом) |
| Фильтр в Caddy на пути «MCP → Multica»: пропускать `GET` и два `POST` предпросмотра, остальное 403 | Даже с токеном из контейнера записать через этот путь нельзя | Не работает, если токен вынесут из контейнера и используют напрямую через публичный адрес Multica | Высокая для пути через MCP |
| Права инструментов в claude.ai: всё, кроме чтения, — Blocked | Защита от ошибки настройки | Только на стороне claude.ai | Дополнительная |

Итог: «только чтение» в полном смысле получится только для вызовов через MCP. **Утёкший токен
отдельного пользователя даст полный доступ участника к одному пространству.** Смягчение:
срок токена 30–90 дней и отзыв в Settings → API Token (`auth-tokens.mdx:22`).

Для фильтра в Caddy контейнер MCP должен ходить к Multica не напрямую в `backend:8080`, а через
отдельный внутренний адрес Caddy с фильтром. Как это устроить в нашей схеме Caddy — работа
для плана агента инфраструктуры (предположение: отдельный `site`-блок на внутреннем порту,
доступный только из сети Docker).

### Б.5. Что будет открыто наружу и как защитить

Наружу открывается один адрес, например `https://multica.autodc.org/<путь>/mcp` или отдельный
поддомен, через Caddy. Через него координатор может читать задачи, статусы и комментарии одного
пространства. Данные уходят в Anthropic: тексты задач и комментариев и ID участников; почту
сервер не запрашивает: среди путей API в `internal/multica/client.go` [S] нет списка участников
`/members` (проверено поиском `/api/` по файлу).

Варианты авторизации, которые принимает claude.ai, с нашим кандидатом:

| Вариант | Как | Слабые места | Объём |
|---|---|---|---|
| **Б-1. Статичный токен** | В claude.ai — Request headers: `Authorization: Bearer <ключ>`; в сервере `MCP_API_KEY` | Доступность на Max не подтверждена [A], [C]; ключ хранится в настройках claude.ai | Минимальный |
| **Б-2. Без входа + фильтр IP + секретный путь** | Caddy пускает только `160.79.104.0/21` [G] и только длинный случайный путь | Диапазон общий для всех клиентов Anthropic: любой, кто узнает путь, может подключить его в свой claude.ai. Путь виден в логах и настройках | Минимальный |
| **Б-3. OAuth** | Перед сервером своя прослойка OAuth (PKCE, DCR или свой client ID, redirect claude.ai) | Свой код авторизации — новая поверхность атаки; готовой подходящей прослойки не найдено | 2–4 дня (оценка) |

Общее для всех вариантов:

- в Caddy — фильтр по IP `160.79.104.0/21` как дополнительный слой;
- ограничение частоты: в установленном Caddy модуля нет (`docs/handoff/2026-10-14-multica-upgrade-plan.md`,
  раздел «Защита входа», пункт 2); на сервере есть только бан после 5 неверных ключей [S];
- логи: сервер [S] пишет тело ответа Multica только на уровне `debug`
  (`internal/multica/client.go:431`) — оставить уровень `info`.

### Б.6. Где запускать

**Основное место — отдельный контейнер на сервере Multica** (условия владельца из PDL-5). Как
выполнить условия в compose — предложение для агента инфраструктуры, не проверялось на сервере:

| Условие владельца | Как выполнить |
|---|---|
| Без доступа к оболочке и файлам сервера | Без томов (`volumes`) с хоста, без `docker.sock`, `read_only: true`, `user` не root, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]` |
| Только API Multica по минимальному токену | Отдельная сеть Docker, где виден только внутренний адрес Caddy с фильтром (Б.4); токен отдельного пользователя |
| Закреплённая версия | Сборка из `Dockerfile` [S] на коммите `5fbfc8e1`; базовые образы `golang` и `alpine` — по digest; итоговый образ — по digest |
| Без выполнения команд | В коде [S] нет пакета `os/exec` (проверено `grep -rln 'os/exec'`, совпадений нет); в образе `alpine` есть оболочка, её можно убрать сборкой на `scratch` или `distroless` (предположение — нужна правка Dockerfile) |

Токен Multica и ключ MCP — в отдельном `.env` с правами 600 рядом с compose, не в репозитории.
Смена токена: выпустить новый у отдельного пользователя, заменить в `.env`, перезапустить
контейнер, отозвать старый.

**Другие места, коротко:**

- **Второй MacBook.** Работает, пока он включён. Нужен туннель наружу (Cloudflare Tunnel или
  ngrok [L]) — ещё один внешний сервис и ещё одна точка входа. Токен лежит на ноутбуке, где уже
  работают агенты.
- **Отдельный недорогой сервер.** Изоляция лучше всего, но ещё один сервер на обслуживании
  (обновления, мониторинг, деньги); к Multica идёт через публичный адрес, фильтр в Caddy
  на пути MCP → Multica не поставить.

### Б.7. Объём работ и действия владельца

Оценка — не проверенная, по опыту похожих задач.

| Шаг | Кто | Время |
|---|---|---|
| Ревью кода [S] на коммите `5fbfc8e1` (запросы к API, логи, отсутствие выполнения команд) | агент | 2–3 ч |
| План инфраструктуры: compose, Dockerfile с закреплёнными образами, Caddy (маршрут наружу, фильтр IP, внутренний фильтр методов) | агент инфраструктуры | 4–6 ч |
| Инструкция для владельца, проверки после запуска | агент | 1–2 ч |
| (Если Б-3) прослойка OAuth | агент | 2–4 дня |

Что сделаете вы:

1. Проверите, видна ли секция Request headers в диалоге Add custom connector (5 минут).
2. Создадите отдельного пользователя Multica: приглашение в пространство с ролью `member`,
   вход по коду (почта не настроена, код — в логе сервера), токен на 90 дней.
3. Добавите DNS-запись, если нужен отдельный поддомен.
4. Выполните на сервере команды из плана по одной: `.env`, сборка образа, запуск, правка Caddy,
   перезагрузка Caddy.
5. Добавите коннектор в claude.ai, отметите инструменты, включите его в чате проекта и проверите.

### Б.8. Расход токенов

Расчёт приблизительный, не измерялся.

- Описания 9 инструментов [S] — порядка 1–2 тыс. токенов контекста в каждом чате, где коннектор
  включён (оценка по длине описаний в `internal/mcp/server.go`). Режим On demand [F] позволяет
  не грузить их заранее.
- Список задач: до 100 задач на вызов в JSON — порядка 10–30 тыс. токенов (оценка). Ответ
  ограничен ~150 000 символов [B]. Экономить: фильтры по статусу и проекту, `limit`.
- Одна задача с комментариями — зависит от длины комментариев; у наших задач отчёты агентов
  бывают длинными, 3–10 тыс. токенов на задачу (оценка).

## А. Выгрузка в знания проекта (запасной вариант, коротко)

Выгрузка доски в Markdown и подключение репозитория к знаниям проекта claude.ai. GitHub в знаниях
проекта доступен на любом тарифе, но обновляется **вручную** кнопкой «Sync now» и берёт только
файлы, без задач и PR [K]. Значит, свежесть — от последней выгрузки и последней синхронизации, а
требование «в реальном времени» не выполняется. Вы также сказали, что ветка с выгрузкой не нужна.
Разумен только если Б окажется невозможен.

## В. Другие варианты

- **Автопилот Multica со сводкой доски.** Агент по расписанию пишет сводку в задачу или файл.
  Координатор её всё равно не видит без А или Б; расходует запуски агентов.
- **Ручная выгрузка одной командой.** `multica issue list --output json` и чтение комментариев,
  результат вы вставляете в чат. Просто и безопасно, но это то же ручное копирование.
- **Встроенный веб-поиск и загрузка страниц claude.ai.** Официально не описано, что они
  умеют входить в закрытые системы; для API-инструмента загрузки сказано, что сайты на
  JavaScript не поддерживаются (https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool).
  Доска Multica закрыта входом — не подходит.
- **Координатор в Claude Code с CLI `multica`.**
  - Что нужно: Claude Code и CLI `multica` на вашем Mac, вход
    `multica login --token <токен отдельного пользователя>` (`server/cmd/multica/cmd_login.go:58`),
    токен хранится в `~/.multica/config.json` с правами 600 (`server/internal/cli/config.go:387`).
  - Только чтение: отдельный пользователь, как в Б.4, плюс в настройках Claude Code разрешить
    `multica issue list/get`, `multica issue comment list` и запретить остальное. Документация
    прямо предупреждает, что правило для Bash «isn't a security boundary around the program»:
    его обходит, например, вызов через `bash -c` [I]. Значит, защита — только отдельный
    пользователь; запрет в настройках — защита от ошибки, не от обхода.
  - Лимиты: на Max они общие для claude.ai и Claude Code: «IDE usage counts toward the same
    usage limits shared across Claude and Claude Code» [J]. Работа координатора в Claude Code
    расходует тот же лимит, что и чат.
  - Минус: координатор уходит из проекта claude.ai в другой инструмент, история и знания проекта
    остаются в чате.

## Рекомендация

Это мнение, не факт.

1. **Сначала 5-минутная проверка у вас:** есть ли Request headers в диалоге коннектора на Max.
2. **Если есть — Б-1:** `strider2038/multica-mcp` v0.2.0 в режиме только чтения, после ревью
   кода, в отдельном контейнере на сервере Multica по вашим условиям, с отдельным пользователем
   Multica, фильтром IP Anthropic и фильтром методов в Caddy.
3. **Если нет — Б-2 как пилот** с тем же набором слоёв и токеном на 30 дней. Риск: утечка
   секретного адреса даёт чтение доски одного пространства любому пользователю Claude. Если риск
   неприемлем — Б-3 (OAuth) отдельной задачей с планом.
4. **На время подготовки** — ручная выгрузка одной командой, как сейчас.

1. Видна ли секция **Request headers** в Customize → Connectors → Add custom connector на вашем
