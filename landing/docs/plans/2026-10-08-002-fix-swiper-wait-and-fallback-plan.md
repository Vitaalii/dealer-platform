# fix: U2 ждёт Swiper, запасной адрес и запасной слайдер

## Summary

U2 перестаёт звать `initGallery` / `initCards`, не дождавшись Swiper. Библиотека грузится с основного адреса, затем при необходимости с запасного. Если не пришла ни с одного, U2 подставляет маленький «статичный» слайдер с тем же API. Скелет больше не остаётся навсегда при любой сети. Меняется только **U2**.

Диагностика — `docs/handoff/2026-10-06-release-lk-tab.md`, раздел «Диагностика: зависание на сером скелете» (`d107459`).

---

## Problem Frame

Сейчас U2 подключает `swiper-bundle.min.js` с `cdn.jsdelivr.net` тегом `async` и, как только пришёл каталог, вызывает `initGallery` → `initCards`. U3 (`#uc-model-swiper`) и U6 (`#uc-gal-swiper`) зовут `new Swiper`, не проверяя, есть ли он.

Если библиотека опоздала, `new Swiper` бросает исключение раньше, чем U3 прячет скелет и шлёт `uc:ready`. Итог: серый скелет и нет Hero. Замер: задержка Swiper на 2,5 с (Haval) или 1 с (Geely) даёт зависание всегда.

---

## Requirements

- R1. При любой доступности CDN скелет уходит, `uc:ready` срабатывает и показывается Hero.
- R2. В обычном случае (Swiper пришёл) — без добавочной задержки: Swiper и данные грузятся параллельно, ждём того, что придёт позже.
- R3. Основной адрес не отвечает или отдаёт не тот файл → запасной адрес с тем же файлом.
- R4. Не пришёл ни с одного → карточки моделей и галерея работают без карусели: стрелки, миниатюры, переключение моделей.
- R5. Перевставляется только U2 (на тестовой — U1 + U2 + U6, они там ещё старые).

## Ответы на вопросы владельца

### 1. Сколько ждать Swiper до запасного пути

**3 с на основной адрес и 3 с на запасной**, отсчёт — от вставки тега. Худший случай — 6 с после `DOMContentLoaded`, затем статичный слайдер. Ошибка загрузки (`onerror`, включая несовпадение integrity) переключает на следующий шаг сразу, не дожидаясь таймера.

Обоснование по замерам (2026-10-07…08):

| Условие | Swiper готов через |
|---|---|
| Из кэша браузера (обычное обновление), настоящий Chrome, 3 страницы × 20 | 0,2–0,6 с от навигации, то есть ~0–0,04 с от вставки тега |
| Холодный кэш, настоящий Chrome (Сингапур) | 1,0–1,3 с от вставки тега |
| Холодный, `curl` из Сингапура | 0,2 с |
| Российские дата-центры (check-host, ответ сервера) | 0,12–0,26 с |

3 с — это 2,3× от худшего измеренного холодного случая, с запасом на мобильную сеть. Ожидание не стоит посетителю ничего лишнего, пока не опоздал и каталог: U2 ждёт `Promise.all` каталога и Swiper. Каталог сам приходит через 0,9–1,7 с после навигации.

Таймеры в фоновой вкладке: страницу, открытую в фоне, Chrome не дросселирует сильнее 1 с в первые 5 минут. Ожидание растянется не больше чем на секунду, это приемлемо.

### 2. Запасной адрес

- **Предлагаю `https://fastly.jsdelivr.net/npm/swiper@11.2.10/swiper-bundle.min.js` (+ `.min.css`).**
  - Файл побайтно тот же: у всех проверенных адресов один SHA-384 — `sha384-2UI1PfnXFjVMQ7/ZDEF70CR943oH3v6uZrFQGGqJYlvhh4g6z6uVktxYbOlAczav`, у CSS — `sha384-gAPqlBuTCdtVcYt9ocMOYWrnBZ4XSL6q+4eXqwNycOr4iFczhNKtnYhF3NEXJM51`.
  - Из российских узлов он стабильно идёт через **Fastly** (151.101.x). `cdn.jsdelivr.net` из России отвечал то через Cloudflare (104.17.x), то через Fastly.
  - Остальные публичные варианты — `gcore.jsdelivr.net`, `unpkg.com`, `cdnjs.cloudflare.com` — сейчас все через **Cloudflare**, то есть в той же зоне риска, что и основной.
- **Честно: надёжного публичного запасного CDN для России нет.** Все проверки — из дата-центров, а замедление Cloudflare у домашних провайдеров оттуда не видно. Fastly — другая сеть, поэтому лучший из публичных, но гарантий нет.
- **Надёжнее — свой адрес в России** (отложено, решение владельца):
  - `static.tildacdn.com` (95.181.182.182, 0,08 с из РФ; если он лежит, не работает вся страница Tilda) — нужно, чтобы владелец загрузил два файла через файлы Tilda и прислал адреса;
  - бот на dockhost (31.186.100.50) — нужен релиз бота и кэш-заголовки (R4).

  Добавить любой из них можно третьим адресом той же цепочкой, без изменения схемы.
- **integrity:** на основной и запасной `<script>` / `<link>` — `integrity` + `crossorigin="anonymous"`. jsDelivr отдаёт CORS. Подменённый ответ (например, HTML-страница провайдера) даст `onerror` и сразу переход на следующий адрес.
- **CSS тоже переключается.** Если основной адрес не ответил, U2 подключает CSS с того же запасного адреса. Без CSS Swiper из запасного адреса разложит слайды неверно.

### 3. Что видит клиент, если Swiper не пришёл ниоткуда

Карточки и галерею — **без карусели, но рабочие**: ни сообщения об ошибке, ни скелета. U2 ставит `window.Swiper` = маленький статичный слайдер с тем же API, что используют U3 и U6. Список методов взят из кода, других обращений нет:
- конструктор `(selector, params)`, `params.loop` (всегда `false`), `activeIndex`, `realIndex`;
- `slideTo`, `slideToLoop`, `slideNext`, `slidePrev`;
- `on('slideChange' | 'slideChangeTransitionEnd')`;
- `update`, `destroy`, `removeAllSlides`.

Как ведёт себя статичный слайдер:
- показывается один слайд (сдвиг `transform` у `.swiper-wrapper`, без анимации), события зовутся синхронно;
- минимальный CSS (`wrapper` — flex, слайд — 100 %) добавляется только в этом режиме;
- работают стрелки, переключение моделей (в том числе жест по ряду названий в U3 — он и так идёт через `goModelSlide`) и миниатюры галереи;
- не работает свайп пальцем по главному фото и плавная анимация слайда.

Порядок в U2: Swiper готов (или статичный) → `initGallery` → `initCards` → `selectComplectation` → скелет скрыт, `uc:ready`, Hero. Плюс страховка: `initGallery` / `initCards` в `try/catch`. Любое исключение → `catalogUnavailable()` (скелет скрыт, `uc:ready`, Hero) и `⛔` в консоль. Вечного скелета не бывает и по другим причинам.

Если настоящий Swiper всё же придёт позже, чем включился статичный, уже созданные слайдеры остаются статичными до перезагрузки. Новые (галерея при следующем входе на шаг 2) создадутся настоящим. Допустимо: внешне различаются только анимацией.

Размер: загрузчик ~0,6 КБ + статичный слайдер ~1,5 КБ после сборки → U2 ≈ 14 КБ из 100 000.

### 4. Другие места без ожидания

Только два вызова `new Swiper` во всех блоках:
- U3 — `#uc-model-swiper` в `buildModelSlider` (из `initCards`);
- U6 — `#uc-gal-swiper` в `setTimeout` внутри построения галереи (из `initGallery` / `updateGallery`).

В U1, U4, U7 Swiper нет, лайтбокс U6 без Swiper. Оба вызова начинаются из `init()` U2, поэтому одного ожидания в U2 достаточно. Гарантию дают и `try/catch`, и статичный слайдер — блоки U3 / U6 не меняются.

Вне темы, но рядом: иконки Tabler тоже грузятся с `cdn.jsdelivr.net` (CSS шрифта). При недоступном jsDelivr пропадут значки, страница работать будет. В эту работу не входит.

## Key Technical Decisions

- **KTD-1. Тег Swiper создаёт JS U2, а не статический `<script async>`.** Иначе нельзя надёжно поймать `load` / `error` (скрипт может выполниться раньше, чем U2 повесит слушатель) и поставить таймер. Вставка из первого `<script>` U2 стартует в том же месте страницы, что и сейчас. Наружу — промис `window._swiperReady` → `'cdn' | 'fallback' | 'static'`.
- **KTD-2. `init()` ждёт `Promise.all([каталог, _swiperReady])`.** В обычном случае задержки нет.
- **KTD-3. Статичный слайдер живёт в U2** — по одной причине: перевставляется только U2.
- **KTD-4. Список адресов — массив в U2** (основной, запасной); третий российский добавляется одной строкой.
- **KTD-5. CSS:** основной — как сейчас (`preload` → `stylesheet`); при переходе на запасной JS добавляется `<link>` на CSS того же адреса.

## Расхождения с планом (по итогам реализации, 2026-10-08)

Решения владельца: ожидание 3 + 3 с — да; российский адрес — через файлы Tilda, файлы загружает владелец; статичный режим без свайпа по фото — достаточно; иконки Tabler — в отложенное.

- **Итог `_swiperReady` — имя хоста** (`cdn.jsdelivr.net`, `fastly.jsdelivr.net`, будущий `static.tildacdn.com`) или `'static'`, а не `'cdn' | 'fallback' | 'static'`. При третьем адресе так однозначно видно, откуда пришло. То же значение — в `window.UC_SWIPER_SOURCE`.
- **Ожидание при трёх адресах.** На каждый адрес — 3 с, на все вместе — 6 с (одобренный предел). Третий адрес успевает, только если один из первых двух ответил ошибкой сразу, а не повис. Порядок и состав — массив `SWIPER_SOURCES` в U2; структура кода от порядка не зависит.
- **CSS Swiper больше не статический `preload`.** Его `<link>` вставляет загрузчик вместе со скриптом того же адреса, с `integrity`. `<noscript>`-ссылка на CSS осталась.
- **Харнесс — отдельная команда `npm run test:swiper`, не в `test:harness`.** Ему нужны сеть и живые страницы, прогон ~10 мин.
  - Сценарии 390 px — подмножество (задержка 0,5 с, +5 с, отказ обоих), полный набор — на 1280 px.
  - «Данные раньше Swiper» проверены сценарием +2,5 с.
  - Скорость перехода на запасной адрес меряется от старта загрузки основного файла: в момент вызова `initCards` входит и ожидание каталога.
  - Итог: 48/48.
  - На старом U2 тот же харнесс падает 5/5: «Swiper is not defined», скелет навсегда.
- **`test:visual` — без дев-стенда, тем же обходом через данные боевого бота.** Исходники против сборки — 18/18 совпадают. Новая сборка против старой из HEAD — 18/18: подключение CSS скриптом вид не изменило.
- **Найдено попутно (не исправлялось, в отложенное):** если нажать кнопку Hero до `uc:ready`, `uc:ready` затем вызывает `goTo(0)`, и посетитель возвращается на Hero. Поведение давнее; с ожиданием Swiper окно до `uc:ready` в худшем случае — до 6 с (раньше в этом случае был вечный скелет).
