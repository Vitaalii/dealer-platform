# Мобильный вьюпорт не эмулируется браузерным инструментом — и что из этого следует

## Context

Проверка вёрстки в этом проекте идёт на живой странице через браузерную автоматизацию: инструмент открывает `demo.autodc.org`, снимает замеры и скриншоты. Для десктопа это работает.

Для мобильного — нет. Изменение размера окна **не меняет CSS-ширину вьюпорта**: замер показывал `innerWidth = 1454` при окне 390px, потому что браузер держал масштаб около 53% (`outerWidth = 779` при `innerWidth = 1454`). Медиазапросы `@media (max-width: 640px)` при этом не срабатывают, и весь мобильный слой остаётся невидимым для проверки.

Естественный обход — форсировать показ мобильного блока через `display: block !important` — порождает вторичную проблему, из-за которой за одну сессию дважды едва не был зафиксирован несуществующий баг.

## Guidance

**Форсированный показ годится для геометрии и логики, но не для Swiper.**

Замерять через `!important`-показ можно: высоты, отступы, зоны касания, вычисленные стили, срабатывание обработчиков, синтетические события. Эти вещи от истории инициализации не зависят.

Нельзя проверять так компоненты, которые меряют контейнер при создании. Swiper, созданный в `display: none`, запоминает нулевую геометрию; последующий форсированный показ её не пересчитывает. Симптом: слайды не двигаются, `transform` враппера остаётся единичной матрицей `matrix(1, 0, 0, 1, 0, 0)`, а `.swiper-slide-active` залипает на одном слайде, пока остальной интерфейс переключается корректно.

**Контрольный тест — способ отличить свой дефект от артефакта стенда.**

Когда добавлен новый путь к существующему поведению, прогоните в одном и том же состоянии подряд новый путь и **все старые, которых правка не касалась**. Если все ведут себя одинаково плохо — виноват стенд. Если новый расходится со старыми — виновата правка.

```js
// В одном состоянии, подряд, без перезагрузки:
document.getElementById('uc-m-next').click();        // существующая стрелка
document.querySelector('.m-hero-name-next').click();  // существующий тап
swipe(vp, 300, 200);                                  // новый жест
// Сравнить: сдвинулось ли фото и transform враппера после каждого
```

Именно этот тест показал, что залипание фотографии принадлежит стенду: `arrowMoved: false`, `tapMoved: false`, `swipeMoved: false` — все три одинаково, при том что стрелка и тап новой правкой не затрагивались.

**Что остаётся за живым устройством.** Ощущение жеста и порог его срабатывания, поведение Swiper при настоящем ресайзе и повороте, `touch-action` и вертикальная прокрутка пальцем. Это передаётся человеку явным списком, а не заворачивается в «проверено».

(Строка про «реальные брейкпойнты медиазапросов» отсюда убрана 2026-09-19: они проверяемы, см. приём ниже.)

## Обход: iframe вместо изменения окна (найден 2026-09-19)

Медиазапросы считаются от вьюпорта **того документа, в котором они действуют**, а для документа внутри `<iframe>` вьюпорт — это сам фрейм. Значит ширину для `@media` можно задать атрибутом, не трогая окно браузера вовсе:

```html
<figure><figcaption>МОБАЙЛ · 390 px</figcaption>
  <iframe src="step1.html" width="390" height="640"></iframe></figure>
<figure><figcaption>ДЕСКТОП · 1100 px</figcaption>
  <iframe src="step1.html" width="1100" height="640"></iframe></figure>
```

Оба состояния живут на одной странице одновременно — их видно рядом на одном скриншоте, и не нужно ни перезагрузки, ни `resize_window`, который в этом окружении всё равно не работает. Замеры берутся через `contentDocument`:

```js
var d = document.querySelectorAll('iframe')[1].contentDocument;
getComputedStyle(d.querySelector('.opts-block')).padding   // "0px 18px" — мобильное правило применилось
```

Так 2026-09-19 проверялся блок «Опции» на шаге 1: на 390px подтвердились `padding: 0 18px`, `flex-direction: column` у индикатора и совпадение левых краёв — то есть ровно тот слой, который раньше считался ненаблюдаемым.

**Когда приём применим.** Всё, что определяется шириной вьюпорта и вычисляется из CSS: срабатывание `@media`, computed styles, отступы и геометрия, порядок `order`, переносы, видимость элементов, совпадение краёв. Плюс визуальная сверка с макетом сразу в двух ширинах.

**Когда неприменим — и почему.**

| Не закрывает | Причина |
|---|---|
| Живую страницу `demo.autodc.org` | Отдаёт `x-frame-options: SAMEORIGIN` — во фрейм не встаёт вовсе. Приём работает только с локально собранной копией страницы |
| Кросс-доменный источник вообще | Даже встав во фрейм, чужой документ не отдаст `contentDocument` — замеров не будет, останется только картинка |
| Тач-события, жесты, пороги | Фрейм даёт ширину, а не сенсорный ввод. Синтетические события остаются синтетическими, `touch-action` и ощущение жеста — по-прежнему за живым устройством |
| Swiper с нулевой геометрией | Корень другой: компонент меряет контейнер при создании. Если внутри фрейма блок скрыт до `uc:step`, слайдер уснёт там точно так же. Фрейм лечит ширину, а не порядок инициализации |
| Масштабирование Zero Block (`t396_initialScale`) | Живёт на настоящей странице Tilda, в локальной сборке его нет |
| `devicePixelRatio`, субпиксельный рендеринг шрифтов | Задаётся устройством, а не размером вьюпорта |

**Как собирать локальную копию.** Стили и разметку тянуть из настоящих файлов блоков дословно (как это делает `docs/testing/phone-validation-harness/build_harness.py`), а не пересказывать — иначе проверяется пересказ. Не забыть ловушку из `CLAUDE.md`: перед блочными стилями вставить `*{box-sizing:content-box}`, иначе переполнения, которые Tilda создаёт на живой странице, локально не воспроизведутся. Высоту фрейма задавать с запасом — иначе внутри появится своя прокрутка и скриншот обрежется.

## Why This Matters

За одну сессию артефакт стенда дважды выглядел как продуктовый баг. В первый раз он едва не попал в отчёт как рассинхрон рядов карусели; во второй — как отказ нового свайпа. Оба раза настоящей причиной был Swiper с нулевой геометрией.

Цена ошибки несимметрична. Ложное «проверено» отправляет в прод непроверенное. Ложное «сломано» отправляет в отладку исправный код — и, что хуже, может привести к «починке» того, что работало.

Отдельно: замер, сделанный не в том состоянии, врёт так же уверенно, как верный. В этой же сессии проверка скролла дала `canScroll: false` только потому, что прокрутка пробовалась вниз на позиции у самого низа страницы. Проверять надо в обе стороны и сверять с `scrollHeight - innerHeight`.

## When to Apply

- Любая правка, живущая только под `@media (max-width: 640px)`.
- Любая проверка, где в цепочке есть Swiper: карусель моделей на шаге 1, галерея на шаге 2.
- Любой отчёт о поведении, которое инструмент физически не мог наблюдать — там нужна явная пометка «не проверено», а не умолчание.

## Examples

**Корректное разделение в отчёте.** Проверено инструментом: место в потоке 43 → 43 px не изменилось, зона касания 19 → 43 px, `box-sizing` применился, синтетический свайп влево дал `next`, вправо — `prev`, движение 15px распознано как тап, мультитач отсечён. Оставлено человеку: ощущение порога 40px, вертикальная прокрутка пальцем, синхронность ряда фотографий.

**Признак, по которому Swiper опознаётся как «спящий»:**

```js
getComputedStyle(document.querySelector('.swiper-wrapper')).transform
// "matrix(1, 0, 0, 1, 0, 0)" — враппер никогда не двигался
```

Живой Swiper после переключения даёт ненулевой сдвиг, например `matrix(1, 0, 0, 1, -1000, 0)`.

**Что будит Swiper.** В этом проекте `u3-card-sliders.html` вызывает `update()` на слайдере при входе на шаг 1 — ровно для того, чтобы измерение произошло на видимом контейнере. В стенде после перезахода на шаг 1 с уже показанным мобильным блоком слайдер оживал, и следующий переход двигал фото и названия согласованно. Один переход — потом геометрия снова устаревала.

## Что осталось непроверенным на 2026-09-13

Всё перечисленное развёрнуто в проде и проверено настолько, насколько позволяет инструмент. На настоящем устройстве не смотрел никто:

- **Высота чёрной полосы на мобильном.** `syncBandHeight` снимает фактическую высоту шапки в рантайме вместо захардкоженных брейкпойнтов — именно потому, что Tilda масштабирует Zero Block через `t396_initialScale` и объявленные 80px на узком экране превращаются в другое число. На десктопе замер даёт 120px, что совпадает со статикой, то есть регресса нет; мобильный результат не наблюдался ни разу.
- **Свайп по ряду названий.** Порог 40px, ощущение жеста, вертикальная прокрутка пальцем по ряду, синхронность ряда фотографий. Логика разрешения жеста проверена синтетическими событиями, `touch-action: pan-y` применяется.
- **Зона касания ряда названий** — 19 → 43px по замеру, но пальцем не проверялась.

Откат свайпа, если он не приживётся: `NAMES_SWIPE_ENABLED = false` в `u3-card-sliders.html` снимает жест целиком, не затрагивая ни тап, ни расширенную зону касания.
