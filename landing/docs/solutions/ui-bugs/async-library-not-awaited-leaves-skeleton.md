# Библиотека с async, которую код не ждёт: вечный скелет при медленном CDN

## Problem

U2 подключал Swiper тегом `<script async>` с `cdn.jsdelivr.net` и звал `initGallery` / `initCards`, как только приходил каталог. U3 и U6 вызывали `new Swiper` без проверки. Если CDN отвечал дольше бота, `new Swiper` бросал `ReferenceError` раньше, чем U3 прятал скелет и слал `uc:ready`. Страница навсегда оставалась на сером скелете, без Hero.

## Symptoms

- После обновления страницы «часто» серый скелет, карточек нет, Hero нет.
- В консоли две ошибки `Swiper is not defined` — галерея (U6, в `setTimeout`) и `initCards` (U3).
- Из Сингапура не воспроизводилось (Swiper из кэша за 0,2–0,6 с, каталог за 0,9–1,7 с). У владельца в России — воспроизводилось: jsDelivr стоит на Cloudflare.

## What Didn't Work

- **Искать регрессию в последних релизах.** Гонка была с первого снимка проекта и в Ver_3: тег `async` и порядок «данные → init» не менялись.
- **Мерить частоту там, где CDN быстрый.** 0 из 60 зависаний в настоящем Chrome ничего не опровергали. Механизм доказала только искусственная задержка одного файла (Playwright, `page.route`): +2,5 с → зависание всегда.

## Solution

- Тег библиотеки создаёт сам скрипт, которому она нужна: `onload` / `onerror` + таймер на каждый адрес, общий лимит, `integrity` (подменённый ответ → `onerror` → следующий адрес), CSS с того же адреса.
- Код, который зовёт библиотеку, ждёт промис готовности вместе с данными. Пока библиотека успевает раньше данных, задержки нет.
- Если адреса исчерпаны — маленькая статичная замена с тем же API, который реально используется (список выписан из кода). Ни одного вызова в других блоках менять не пришлось.
- Построение экрана — в `try/catch` с выходом в штатный «каталог недоступен». Никакое исключение не оставляет скелет навсегда.

## Prevention

- Внешняя библиотека с `async` + код, который её вызывает по другому событию (данные с сервера), — гонка. Либо ждать явно, либо `defer` и вызов после `DOMContentLoaded`.
- Экран, который прячет скелет только в конце длинной цепочки, обязан иметь выход при исключении в любом её звене.
- Проверять порядок нужно задержкой конкретного файла, а не «20 обновлений из своей сети».
- Одинаковость файла на разных CDN проверяется SHA-384 — тогда один `integrity` годится для всех адресов.

Проверка — `npm run test:swiper` (`tools/swiper-fallback-check.py`).
